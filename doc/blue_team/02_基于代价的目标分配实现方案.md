基于代价的蓝队炸弹目标分配实现方案
================================

文档性质：可直接指导编码的设计稿，不代表这些模块已经实现。
适用范围：蓝队 rescue 模式；与 01_系统化多机探索实现方案共享接口。
源码基准：当前 `my_drone_blue_basic.py`；所有阈值均为首版建议值。

1. 当前代码事实与问题

实际读取并核对的项目文件：

- `src/swarm_rescue/solutions/my_drone_blue_basic.py`：当前蓝队控制器。
- `src/swarm_rescue/solutions/my_drone_rescue_example.py`：现成抓取、运动、
  Lidar 脱困和投放方法。
- `src/swarm_rescue/simulation/drone/drone_abstract.py`：可用测量 API、
  `grasped_bombs()`、健康值、`reward`、通信器和单爪限制。
- `src/swarm_rescue/simulation/drone/communicator.py`：局部通信实现。
- `src/swarm_rescue/simulation/drone/drone_sensors.py`：GPS、指南针噪声。
- `src/swarm_rescue/simulation/ray_sensors/drone_semantic_sensor.py`：
  语义数据字段、噪声和观测范围。
- `src/swarm_rescue/simulation/utils/constants.py`：量程、通信半径与健康上限。
- `src/swarm_rescue/submission_check.py`：提交包和禁用真值 API 检查。
- `src/swarm_rescue/simulation/gui_map/gui_sr.py`、`playground.py`、
  `simulation/elements/disposal_center.py`、`simulation/drone/agent.py`：
  用于核实控制与消息时序、回收奖励事件。

当前 `MyDroneBlueBasic` 将炸弹记在 `_bomb_memories` 中；
`_peer_claims` 只记录 `(坐标, 接收步, 携带标志)`；
`_claimed_by_preferred_peer()` 基本按较小 id 解决冲突。
`_choose_visible_bomb()` 和 `_choose_remembered_bomb()` 先选目标，
随后分别调用父类 `_control_chase_bomb()` 和本类的记忆目标导航。
这是可运行的基础策略，但不能比较绕墙距离、回收难度、健康和定位质量。

语义传感器有 35 条射线，量程 200 像素；`Data` 含 `distance`、
`angle`、`entity_type`、`grasped`，不含炸弹稳定实体 id。
测距约有 2.5 像素标准差；GPS 和指南针也带噪声。
语义层还主动过滤墙体，因此路径风险须由 Lidar/占据图提供。
通信半径为 250 像素，通信器一次只能发送一个消息对象。
`DroneAbstract` 用 `Grasper(max_grasped=1)`，携弹机不再竞拍。

消息真实时序必须按下列流程实现：

```text
仿真周期 t：
  GuiSR.collect_all_messages() 先调用 define_message_for_all()
  此时读取的是上一控制周期缓存的包
  GuiSR 再调用每架无人机的 control()
  Playground.step() 执行物理、感知并发送刚收集的包
仿真周期 t+1：
  对端 control() 才能处理 t 末传到 received_messages 的包
```

所以 `control()` 在 t 算出的竞价，通常要到 t+1 才广播，
对端 t+2 才根据它改变决策；协议不得假定同一步握手。
`received_messages` 会在每次 `Communicator.pre_step()` 清空。

另有一个需要优先修正的现有风险：`control()` 中从携弹变为未携弹
就调用 `_mark_current_target_cleared()`；意外掉落也会被标为已清除。
真实销毁由炸弹进入配对 `DisposalCenter` 触发，该逻辑给无人机
`reward` 加分并移除炸弹。`Agent.pre_step()` 会把奖励清零，
因此控制周期内的正奖励只表示最近一个物理步的事件，必须当步读取。

2. 方案目标和非目标

目标是用可解释、可过期的本地代价竞价替换 id 优先声明：

1. 每个已发现炸弹建立可追溯、能跨机合并的轨迹。
2. 每架空闲无人机用同一尺度评估取弹、返航、健康与风险。
3. 局部通信连通时，在有限传播延迟后收敛到一个有效执行者。
4. 断联时允许暂时重复追踪，重连后确定性让败者退出。
5. 抓取、掉落、确认回收都有不同状态；旧消息不能复活已清除目标。
6. 没有 GPS、A*、回收坐标或通信时仍能安全退化。

非目标：不实现全图建图、A*、返航控制、机械爪动作或官方评分器；
不读取地图真值、炸弹实体 id、真实坐标或别人的内部状态；
不保证永远断联的无人机达成全局一致，也不承诺所有地图分数提升。
本模块只返回“谁负责哪个目标”和简短通信意图，不返回运动命令。

5. 数据模型和状态枚举

公开 dataclass 建议如下；为兼容项目声明的 Python 3.8 下限，
公开类型标注用 `typing.Tuple`、`Optional`，不要依赖运行时泛型内建。

```python
from dataclasses import dataclass
from typing import Optional, Tuple

WorldPoint = Tuple[float, float]

@dataclass(frozen=True)
class PoseEstimate:
    position: Optional[WorldPoint]
    heading: Optional[float]
    position_variance: float       # px^2
    heading_variance: float        # rad^2
    source: str
    frame_id: str
    step: int
    valid: bool

@dataclass(frozen=True)
class BombTrack:
    track_id: str                  # "bomb:world:d6:17"
    position: WorldPoint           # 取弹目标位置，世界 px
    position_variance: float       # px^2；标量、近似各向同性
    confidence: float              # [0, 1]
    status: str
    owner_id: Optional[int]
    last_seen_step: int            # 本机最近一次证据步
    revision: int                  # 单 track 本机修订号
    frame_id: str = "world"
    origin_id: int = -1

@dataclass(frozen=True)
class TaskBid:
    track_id: str
    bidder_id: int
    epoch: int
    total_cost: float             # [0, 1]，越低越好
    lease_steps: int
    created_step: int             # 发送方仿真逻辑步
    cost_terms: Tuple[Tuple[str, float], ...]
    epoch_origin: int = -1
    bid_seq: int = 0

@dataclass(frozen=True)
class AssignmentDecision:
    status: str
    track_id: Optional[str]
    owner_id: Optional[int]
    target_position: Optional[WorldPoint]
    winning_cost: float           # IDLE 等无赢家状态用 1.0
    epoch: int                    # 无任务用 -1
    lease_until_step: int         # 本机时钟；无租约用 -1
    reason: str

@dataclass(frozen=True)
class BombObservation:
    position: Optional[WorldPoint]  # 世界点；无世界位姿时为 None
    ray_angle: float                # 机体系弧度
    distance: float                 # 语义量测 px
    position_variance: float        # px^2
    source_id: int
    source_step: int
    frame_id: str
    is_local: bool

@dataclass(frozen=True)
class DecodedTaskEvent:
    kind: str                       # S/B/L/C/D/X/R/A
    sender_id: int                  # 最后一跳发送者
    origin_id: int                  # 原事件创建者
    sender_step: int
    received_step: int              # 本机接收步
    seq: int
    frame_id: str
    track_id: Optional[str]
    position: Optional[WorldPoint]
    position_variance: Optional[float]
    epoch: int
    epoch_origin: int
    cost_milli: Optional[int]
    owner_id: Optional[int]
    ttl_steps: int
    lock_steps_left: int            # 接收时剩余锁定步数，上限 25
    aliases: Tuple[str, ...]
    event_id: Optional[str]
    hop: int
    evidence: Optional[str]

@dataclass(frozen=True)
class TaskInput:
    step: int
    round_steps_left: int
    drone_id: int
    health: int
    pose: PoseEstimate
    carrying: bool
    reward_delta: float
    release_commanded_last_step: bool
    local_bomb_hits: Tuple[BombObservation, ...]
    peer_packets: Tuple[DecodedTaskEvent, ...]
    disposal_position: Optional[WorldPoint]
    disposal_frame_id: Optional[str]
    return_route_length: Optional[float]
    return_route_status: str
    mode: str

@dataclass(frozen=True)
class TaskOutput:
    decision: AssignmentDecision
    goal: Optional[NavigationGoal]
    selected_track: Optional[BombTrack]
    has_active_task: bool
    occupied_tracks: Tuple[str, ...]
    task_payload: Optional[dict]
    debug_cost_terms: Tuple[Tuple[str, float], ...]
```

`BombObservation.position` 是语义表面命中的世界点，目标中心估计
由 track store 完成；方差包括位姿、测距和角度误差。
无世界位姿时保留射线数据供控制器近距抓取，但轨迹分配器不把
`position=None` 观测用于跨机位置竞价。
`DecodedTaskEvent` 是校验过的内部对象，不直接上广播；某事件
不适用的字段以 None、空 tuple 或 -1 表示。路径服务签名见第 9 节。

`BombTrack.status` 完整集合：

```text
AVAILABLE  已确认未被占用，可竞拍
AUCTIONED  至少有一份有效 bid，尚未稳定获胜
ASSIGNED   已有有效 lease；可以开始靠近
CARRIED    已观测到实际机械爪持有，禁止其他机追踪
LOST       目标在预期位置反复未被重获；暂时冻结
CLEARED    收到可信回收证据；保留墓碑
EXPIRED    记忆寿命到期或回合结束；可从活跃索引移出
```

投放失败不是 `CLEARED`：以 `AVAILABLE` 重开新 epoch，必要时先短暂
`LOST` 等待重新观测。`CARRIED` 只由真实抓取边缘或带有效 owner
租约的携带消息产生，不能仅因有人宣称看到了炸弹就进入。

`AssignmentDecision.status` 完整集合：

```text
IDLE       无合格炸弹；可探索
BIDDING    正在等待本地竞价窗口结束
WON        本步确认本机赢得租约，尚未开始导航
LOST       本轮竞价失败，等待换下一个候选
EXECUTING  已获任务并正追踪、接近或抓取
CARRYING   机械爪实际有弹；停止竞价并返航
RELEASED   正常完成或主动放弃；本步发释放/清除事件
CANCELLED  轨迹合并、墓碑或错误导致当前任务作废
```

状态迁移约束：`IDLE -> BIDDING -> WON -> EXECUTING -> CARRYING`；
`BIDDING/EXECUTING -> LOST/RELEASED/CANCELLED -> IDLE`；
`CARRYING -> RELEASED` 只有收到回收确认；
`CARRYING -> LOST` 表示掉落但未销毁，随后轨迹重开竞价。
`WON` 可只存在一个 `update()` 返回周期，不要求物理停留。

内部还需 `PeerBid`、`LeaseRecord`、`TrackAlias`、`Tombstone`、
`PendingDrop`；它们不必进入公共契约。所有这些状态均以本机
`step` 计过期，不用墙钟秒。一次更新中先应用抓取/回收硬事件，
再合并传感器与消息，最后才计算竞价，避免半步中间态外泄。

6. 目标轨迹关联

6.1 坐标与单帧聚类

世界坐标必须由 `PoseEstimate` + 语义射线变换得到，
只在 `pose.valid`、`pose.frame_id == "world"` 时用于跨机竞拍。
语义距离是射线击中炸弹表面，不是炸弹中心；首版可沿射线方向
补偿约 12 像素半径，并将此模型误差并入方差。若仿真实测发现
形状导致偏差，改用不补偿的表面命中簇，但全队必须用同一种定义。

同一帧先把 `grasped=True` 的命中排除；非有限或超量程命中丢弃。
按射线角度排序，基于中心估计做“有界完全连接”聚类：
候选到簇中每个成员距离不大于 26 像素、簇直径不大于 28 像素，
且角度相邻或属于同一连续射线段，才可加入。禁止链式单连接，
否则两枚近邻炸弹会被桥接。每簇用逆方差加权均值和中位数
交叉校验，离群射线丢弃。只有一条射线时保留但降低置信度。
同帧两组互不重叠射线若中心相距大于约 30 像素，保留两个候选；
更近且不可分辨时标 `AMBIGUOUS` 内部标志，不强行假定是一枚。

观测方差近似：

```text
sigma_xy^2 = pose.position_variance
           + (distance^2 * pose.heading_variance)
           + semantic_range_variance
           + bomb_surface_model_variance
```

首版把 `semantic_range_variance` 设为 `2.5^2`，表面模型方差
至少 `8^2`；这是保守估计，不是官方严格统计模型。GPS 噪声是
时间相关的，同一机连续观测不得当成独立样本无限降低方差；
融合方差设置 64 px^2 下限，置信度按不同时间和不同源缓慢提升。

6.2 跨帧一对一关联

对同一 frame 的活动 track 和本帧簇计算：

```text
gate = min(45, max(22, 2.5 * sqrt(track_var + obs_var)))
eligible = distance(track_center, observation_center) <= gate
```

先排除墓碑、CARRIED、明显速度不合理和 `LOST` 冷却目标。
在合格边上按 `(归一化距离, track_id, observation_index)` 排序做
一对一贪心匹配；10 机、几十目标足够快。一个观测绝不能更新
两个轨迹。跨帧如果炸弹自然移动，使用最近两次观测的限速预测点；
只有连续两帧支持移动才更新速度，否则视为测量噪声。
超过 360 步未见且无有效租约的轨迹转 `EXPIRED`；
去目标位置近距扫描 12 步仍不见，则先 `LOST` 60 步再复核。

6.3 ID 与跨机合并

本机新 ID：`bomb:<frame>:d<origin_id>:<monotonic_counter>`。
回合开始重置计数器和全部轨迹；ID 不含精确坐标。
消息中同时带 `frame`、坐标、方差、最近源观测时间与 revision。
只合并同 frame 轨迹，且两个源的近期独立证据位置满足 gate；
有同帧两枚明显独立炸弹的反证时禁止合并。
合并后以 `(首见步, origin_id, counter)` 字典序最小的 ID
作为 canonical ID，其他 ID 进入 alias 映射 360 步；
广播一条 `ALIAS` 事件 `(old_id, canonical_id, evidence_step)`。
bid、lease、clear 进入状态机前先 `resolve(id)`。
两个竞争者对别名认识不同时，靠 `ALIAS` 事件最终对齐；
新连通后必须先处理 alias 再仲裁 lease。

如果同一轨迹后期有两个持续分离的观测簇，且持续 3 帧、
中心距超过 30 像素，同时各自能一对一匹配历史观测，执行分裂：
证据更多的一支继承旧 ID，另一支取得新 ID，旧 bid/lease 只留在
继承支；新支单独竞拍。若证据不足，不分裂并标记位置不确定。
已经 `CLEARED` 的 ID 绝不分裂为活目标；新看到的物体创建新 ID。

6.4 携带、掉落与墓碑

本机 `grasped_bombs()` 从假变真时，把当前执行 track 原子标为
`CARRIED(owner_id=self)`；如果当前没有 track，则把最近 20 步内、
最近的可见 track 关联，仍找不到时建一个 `carry:unknown:d<ID>`
占位 ID。携带时不再把随无人机移动的炸弹当作静止可竞拍目标。
队友的 `CARRY` 消息按 track ID 或别名更新状态；只有它与一份
近期有效任务租约、近期近距观测相符时，才压过旧竞价。

本机从携带变未携带时：

- 若当步 `reward_delta > 0`，且前一周期确实携弹，创建 `CLEARED`
  墓碑；可以额外核对近期回收区接近事实，但不要因未知回收区否定
  有效奖励。`reward` 必须在本步读取，不能下一步追溯。
- 若无正奖励，不发 `CLEAR`。记录 `PendingDrop`，广播 `DROP`，
  原任务释放；等待本机语义重获或队友看到炸弹，重新竞拍。
- 若自机从未携弹却得到正奖励，可能是无人抓取炸弹接触回收区而
  记到最近无人机；没有可靠 track 关联时只记日志，不凭空清除
  附近全部目标。

墓碑记录 `(canonical_id, aliases, last_position, evidence_step,
origin_id, revision, received_step)`。有效期建议本回合内保留，
至少 360 步；广播重复 3 次并在邻居重连时优先重传。
旧 sighting/旧 lease 如其 `source_step <= evidence_step`，且 ID
或 alias 命中墓碑，直接拒绝；不靠“附近 68 像素全都消失”判定，
否则会错误抹掉相邻的第二枚炸弹。新鲜本地直视证据若反复出现，
应新建 ID 并保留审计记录，不能复活旧 ID。
若旧消息 ID 尚未并入已知 alias，却落在墓碑 gate 内，
先放入 `QUARANTINE` 待核对而不立刻激活、不直接永久删除；
只有新的本机直视证据或两个独立来源的后续证据，才能把它作为
新炸弹建立新 ID。这兼顾未知别名与相邻第二枚炸弹。

7. 代价函数和数值示例

采用任务总成本越小越好的约定，所有有限项先映射至 `[0,1]`。
距离标尺 `D = max(world_width, world_height, 400)`，地图尺寸未知时
暂用 1250 只是归一化回退参数，不可当地图坐标；更稳妥是从
过去可用路径的滚动 P90 学习 `D`，但首版可用 `size_area`。

```text
C = 0.34 * P + 0.18 * R + 0.14 * H + 0.12 * O
  + 0.08 * U + 0.09 * S + 0.05 * L
```

`P` 取弹路径：A* `READY/AT_GOAL` 时用 `min(length/D, 1)`。
若 `BUDGET_EXCEEDED`、`STALE_MAP` 或 A* 尚未接入，用
`min(1, 1.35 * euclidean/D + 0.15)`，同时标记“估计未验证”。
若连续两版占据图明确 `NO_PATH`，本 track 进入 60 步冷却，不出价；
若地图未知，不能把一次 `NO_PATH` 当成永久不可达。

`R` 取弹点到对应回收区的携弹路径长度 / D。
优先问返航模块是否有从该炸弹邻域到回收区的可用 route；
否则询问规划器 `carrying=True` 的路线；若没有规划器而已知
回收区坐标，用 `1.35 * euclidean/D + 0.15`；未知回收区时取 0.65。
这项对同一炸弹的各无人机大体相同，但能在比较多枚炸弹时
避免优先拿难以送回的目标。不能凭未经验证的直线距离命令穿墙。

`H = clamp((25 - health) / 25, 0, 1)`；`health <= 8` 为硬禁投条件，
健康缺失按 0 处理并禁投。上限 50 来自 `DRONE_INITIAL_HEALTH`。
低健康机如果已经携弹仍按返航策略执行，不会因为禁投而丢弃炸弹。

`O` 是路径上风险均值：占据图沿取弹路径采样墙边、未知格和狭道，
返航路径可加权取最大风险。无图时用近期 Lidar 前方阻挡率，
再缺失时取 0.5。`U = min(1, sqrt(position_variance)/40)`；
若非 `world` 位姿或 `valid=False`，不生成跨机可比的世界坐标 bid。

`S=0` 表示继续当前目标；新目标一般 `S=1`；原目标已清除、失效或
不可达时 `S=0`。此外保持原目标的租约至少 25 步，除非
`new_cost + 0.12 < current_cost` 或有硬事件，防止反复换任务。
`L=0` 表示空闲，正在执行另一目标且未释放时 `L=1` 并原则上
不双重出价；携弹时直接禁投，不用有限大代价模拟禁投。

所有 7 项权重相加为 1；广播 `round(C, 3)` 或整数千分值，
内部计算仍用未舍入数。赢家比较用可重复的整数分档：

```text
cost_milli = int(round(1000 * clamp(C, 0, 1)))
```

不同无人机只比较同一目标的报价；当只有一个有效竞买者时，
即使成本较高也能获得任务。若局部规划明确不可达，60 步后
重新检查，不会永久封死远处但唯一可达的目标。
剩余时间少于估计取弹+返航所需步数时可降低竞价优先级，
但速度估算不可靠时不设硬禁投，防止全队放弃。

数值例子，同一枚弹、地图尺度 D=1250：

```text
无人机 6：P=.20, R=.32, H=.00, O=.10,
          U=.20, S=.00, L=.00
          C=.34*.20+.18*.32+.14*.00+.12*.10+.08*.20
           =.1536 -> 154/1000

无人机 2：P=.14, R=.32, H=.60, O=.35,
          U=.10, S=1.00, L=.00
          C=.34*.14+.18*.32+.14*.60+.12*.35+.08*.10
           +.09*1 =.3292 -> 329/1000
```

虽然 2 号更近，6 号的健康和路线风险更优，6 号获胜。
如果 6 号已携弹，它根本不出价，2 号仍可获胜。

可执行伪代码：

```text
for track in available_tracks:
    if carrying or health <= 8 or not comparable_world_frame:
        continue
    pickup = routes.estimate_cost(pose.position, track.position, False, 500)
    if hard_no_path_after_recheck(track, pickup):
        put_on_cooldown(track, 60)
        continue
    return_cost = estimate_return(track, disposal, return_route, routes)
    terms = normalize(pickup, return_cost, health, risk, pose,
                      target_switch, current_task)
    bid = TaskBid(track.id, drone_id, epoch.number,
                  weighted_sum(terms), 45, step, tuple(terms),
                  epoch.origin, next_seq())
choose_lowest_cost_candidate_with_hysteresis()

```

8. 分布式竞价与租约协议

8.1 epoch 和本地竞价窗口

每个 canonical track 有 auction token `(epoch, epoch_origin)`。
首次创建本地轨迹时取 `(1, creator_id)`；别名合并时采用已知 token
中字典序最大的一个，只有 lease 过期、主动释放、赢家失联或
硬失败后，才允许重开为 `(max_seen_epoch+1, opener_id)`。
听到更高 token 就采纳，不再同时自己加一；仅发现同一目标的
新坐标不能重开 epoch。`epoch_origin` 必须进入消息，避免
两个无人机各自产生相同数字但实际不同轮次。

首次观测后进入 8 步本地收集窗口。窗口内广播本机一份 bid，
缓存对端有效 bid；无竞争者时 8 步后自赢。窗口结束后按当前
可见邻居判断赢家；迟到更低成本的有效 bid 可以抢占未抓取者，
但执行者 25 步锁定期内除非新成本比其优 0.12 以上，
不会被轻微浮动抢占。为使双方算出相同结果，锁定期剩余步数、
锁定期间获胜价须在 lease 中广播；接收方用本地接收步加
`min(lock_steps_left, 25)` 推算本地截止步。收到缺这些字段的
旧版消息时不执行抢占，只等租约过期。

8.2 排序和状态

所有报价的比较顺序固定：

```text
先比较 token：epoch 数字较大优先；相同时 epoch_origin 较大优先
同 token 内：cost_milli 较小优先
成本相同：bidder_id 较小优先
同一 bidder 重报：bid_seq 较大优先，仅更新该机报价
```

该规则是确定性全排序，不依赖某无人机自己的隐含信息。
`CARRIED` 证据优先级高于任何普通 bid 和 lease；可信 `CLEAR`
高于 `CARRIED`。已失效、过期或不同 frame 报价不参与排序。
如果一个人对同一目标同时发 bid 和 lease，以较新 seq 为准。

赢家发送 `LEASE(track, token, cost_milli, ttl=45, lock_ttl)`；
每 12 步续租一次。收到 lease 的节点记录
`expiry = local_received_step + min(ttl, 45)`；若连续 45 步
收不到续租，在自己的本地时钟上失效，并新开 epoch。
发送者的 `step` 和 `seq` 只用于去重与旧包检查，
不能直接当接收方的到期时间。`CARRY` 心跳每 12 步续一次，
短暂丢包不会立刻解封已抓取目标；45 步后若未获新证据，
转 `LOST` 并要求本地视觉复核，不直接认定炸弹凭空消失。

8.3 局部分区和重新连通

250 像素通信只保证当前邻居交换，绝不声称全队原子共识。
两个互不可见的机可能都认为自己是赢家；若后来近距离遇见，
先对齐 alias、取最高 epoch，再按成本/id 排序，败者发送
`RELEASE(reason="split_brain_lost")` 并换目标。若一方已真正携弹，
它优先，另一方立即停止追踪。不同连通分量中的暂时重复追踪
是允许的可度量退化，不应让两机都停在原地等待中心节点。

首版只对 `CLEAR`、`CARRY`、`ALIAS` 事件允许最多 2 跳转发；
bid/lease 只在直接邻居间竞价，避免多跳陈旧成本带来的假共识。
转发事件带 `(origin_id, seq, event_id, hop)`；每台机维护最近
128 个 `event_id` 的去重缓存，`hop` 每转一次加 1，达到 2 丢弃。
转发只能占外层包的一个 task 槽；本机 `CLEAR`、`CARRY`
心跳优先，不允许地图补丁阻塞关键任务事件。

8.4 释放原因

健康降至 8 或以下、当前路线经复核确实 `NO_PATH`、
位置 frame 不再可比较、目标 12 步扫描仍不见、
对端赢家更优、墓碑出现或持弹状态变化，均可结束当前普通任务。
主动放弃必须带 `RELEASE`，本机立即清除旧 lease；
远端在收到释放前最多会等到租约 TTL 到期。
传感器暂时无效不必立即放弃，可保留 5 步短暂状态，
但不能继续广播新 bid。

9. 输入契约

由协调器每步构造一个 `TaskInput`；所有字段都必须有来源和缺失策略。

- `step: int`：仿真逻辑步。来源 `elapsed_timestep`；本机单调。
  模块不直接读取墙钟。若异常回退，先 `reset()`。
- `round_steps_left: int`：地图配置提供的步数上限减当前步；
  未知时传 `-1`，不做截止硬判断。
- `drone_id: int`：`identifier`；唯一且本回合不变。
- `health: int`：`drone_health`，范围 0 到 50；缺失禁投。
- `pose: PoseEstimate`：定位模块输出，世界坐标 px、航向 rad、
  方差 px^2/rad^2、frame 和 step；无效时只保留携弹返航。
- `carrying: bool`：`bool(grasped_bombs())`；硬优先，
  不能用其他无人机的宣称覆盖本机实际传感器。
- `reward_delta: float`：控制器当步读取 `self.reward`，通常为 0；
  仅用于匹配自己上一周期的携弹边缘，不当成总累计分。
- `release_commanded_last_step: bool`：控制器缓存上周期 grasper=0；
  与 reward 一起诊断掉落，但正奖励是确认清除的核心证据。
- `local_bomb_hits`：本机语义观测经统一定位投影得到，
  时间戳为本步；无 GPS 也可保留机体系射线供近距追踪，
  但不生成跨机世界 bid。
- `peer_packets`：`message_codec` 已验证包，含接收本机步数、
  sender、task payload；无通信时传空 tuple。
- `disposal_position` 和 `disposal_frame_id`：语义发现、
  队友消息或返航模块定位所得；未知传 None，不使用硬编码位置。
- `return_route_length`、`return_route_status`：返航模块给出
  携弹路径长度 px 与 `READY/UNKNOWN/NO_PATH`；不可靠时走
  已知回收点的 A* 或惩罚化几何回退。
- `mode`：协调器的 `EXPLORE/TASK/CARRY/RECOVER`；用于判断
  切换成本，不替代 `carrying` 真值。

路径、栅格由协调器作为只读服务参数传入：

```python
class RouteCostProvider(Protocol):
    def estimate_cost(
        self,
        start: WorldPoint,
        goal: WorldPoint,
        carrying: bool,
        max_expansions: int,
    ) -> Tuple[str, float, int]: ...

class OccupancyRiskView(Protocol):
    revision: int
    frame_id: str
    def path_risk(self, path_or_segment) -> float: ...
```

`estimate_cost()` 返回 `(status, length_px, map_revision)`；
允许 `READY`、`AT_GOAL`、`NO_PATH`、`BUDGET_EXCEEDED`、
`STALE_MAP`、`NO_POSE`。风险返回 `[0,1]`，缺图用 Lidar
阻挡率或 0.5。注意 01 探索文档提出的路径接口为三参数版本；
最终共享接口应统一成上述携弹参数或提供适配器，不能在运行时
让两个模块调用签名不一致的同名方法。轨迹候选的时间戳以本机
收到时刻计算，不能把队友的 `step` 直接当本机 TTL。

10. 输出契约

`TaskAllocator.update(data, routes, grid) -> TaskOutput`。

`decision` 给 `BlueCoordinator` 决定主任务；`selected_track` 和
`goal` 给炸弹导航层，`goal.kind="BOMB_PICKUP"`，
`goal.goal_id` 等于 canonical track ID，目标容差初值 24 像素。
直接可见时协调器将匹配到该 track 的原始 `SemanticHit`
送 `_control_chase_bomb()`；只在记忆中时把世界点送导航器。

`has_active_task` 给探索模块：`WON/EXECUTING/CARRYING` 为 True；
`BIDDING` 可选择 True 并短暂停顿，超过 8 步不得阻塞探索；
`IDLE/LOST/RELEASED/CANCELLED` 为 False。
`occupied_tracks` 是同 frame、有效 lease/carry 的 canonical ID
元组，探索模块可用它避开重复热点，但不修改轨迹状态。
`task_payload` 是一个任务子消息，交给统一 codec；
`debug_cost_terms` 只供日志和单元测试，不上广播包。

完整示例：

11. 消息格式和实际示例

统一外层包仍与 01 探索方案一致：一个包容纳多个模块各自一个摘要。
以 `kind="blue-team-v2"`、`v=2` 作为版本门槛；
`task` 一步最多一个事件，`explore` 一步最多一份租约，
`map` 只允许稀疏摘要且不得挤占任务事件预算。

```python
{
    "kind": "blue-team-v2", "v": 2, "id": 6, "step": 760,
    "seq": 91, "n": 10, "frame": "world",
    "pose": [140.0, -35.0, 120.0],
    "task": {"k": "B", "tid": "bomb:world:d6:17",
             "p": [138.0, -34.0], "var": 90.0,
             "e": 3, "eo": 6, "c": 154,
             "ttl": 12, "ts": 760, "q": 17},
    "explore": None, "map": None
}
```

`k` 事件类型：`S`=sighting，`B`=bid，`L`=lease，
`C`=carrying，`D`=drop，`X`=verified clear，
`R`=release，`A`=alias。`p` 是 world px，`var` 是 px^2，
`e/eo` 为 epoch token，`c` 为整数千分成本，`q` 是任务事件 seq，
`ts` 是源逻辑步；坐标传有限数字并最多保留 1 位小数。

lease 续约例：

```python
{"k":"L", "tid":"bomb:world:d6:17", "p":[138.0,-34.0],
 "e":3, "eo":6, "c":154, "owner":6, "ttl":45,
 "lock_ttl":13, "ts":772, "q":18}
```

携带例：

```python
{"k":"C", "tid":"bomb:world:d6:17", "owner":6,
 "e":3, "eo":6, "ttl":45, "ts":774, "q":19,
 "event":"carry:6:19", "hop":0}
```

确认清除墓碑例：

```python
{"k":"X", "tid":"bomb:world:d6:17", "p":[138.0,-34.0],
 "aliases":["bomb:world:d2:4"], "e":3, "eo":6,
 "proof":"reward_after_carry", "ts":812, "q":20,
 "event":"clear:6:20", "hop":0}
```

无任务最小包仍要发，以便探索模块通信：

```python
{"kind":"blue-team-v2", "v":2, "id":6,
 "step":813, "seq":95, "n":10, "frame":"world",
 "task":None, "explore":None, "map":None}
```

字典中只含 Python `dict/list/str/int/float/bool/None`；
不发送 NumPy 数组、dataclass、完整轨迹或完整地图。
任务包单次最多一条目标事件、两条 alias、一个坐标；
超过约 512 字节先丢 `map`，再丢非关键 `pose`，
绝不截断 `X/C/R`。事件优先级：本机 `X` > 本机 `C/D`
> 必要的 `R/A` > 到期前 `L` > 首次 `B` > `S`。
高优先级事件至少重复 3 次，但重复 `event_id` 不延长 TTL。
定期 sighting 可在没有更高事件的空闲步发送。

验证函数最终签名建议：

```python
def validate_task_payload(
    raw_task: object,
    packet_step: int,
    receiver_step: int,
    sender_id: int,
    frame_id: str,
) -> Optional[DecodedTaskEvent]: ...
```

解码必须检查 `kind/v`、最外层和事件 seq、ID 长度、`ttl` 上限、
有限坐标/方差/成本、frame、`owner==sender`（原始非转发包）、
事件时间是否过远、alias 数量，以及 `task` 是否为 dict 或 None。
转发包保留 `origin` 并以签名外的 `sender_id` 标明最后一跳；
没有密码学签名，不能抵抗恶意伪造，只解决正常竞赛环境下的数据错误。
不兼容版本或 malformed 包直接丢弃，不能让控制函数异常退出。

接收 TTL：`expires_local = received_step + min(ttl, cap)`；
若同一 `(origin, q)` 已看过则不刷新过期时间。发送端 `step`
可用于检测同回合明显过旧的包，例如超过 90 步；不能直接
转换为本机租约截止时间。通信重连后的旧包若 source_step 早于
墓碑证据，仍需拒绝。

v1 迁移顺序：先让 codec 同时读 `blue-basic-v1` 和 v2，
把旧 `claim/sighting/carrying` 转成低置信度观测或临时 lease；
旧 `cleared` 只有坐标、没有奖励证据，不能直接转成强墓碑。
确认所有控制器都使用 v2 解析后，才切换发送端 kind；
仅在 v2 包中保留旧字段而不修改旧 `_ingest_peer_messages()`
没有用，因为它会先按 kind 拒绝整个消息。

12. 单步调用时序

设计成一次 `control()` 内的确定性流水线：

```text
1. 读当步 measured_gps_position、compass、semantic、lidar、
   drone_health、grasped_bombs、reward、elapsed_timestep
2. 定位模块产出 PoseEstimate；语义点投到世界 frame
3. codec 解码 received_messages，过滤过期/错版/恶意尺寸包
4. TaskAllocator 先处理本机 reward 和携带状态边缘
5. 再处理 peer CLEAR/ALIAS/CARRY，再合并普通观测和 bid/lease
6. 轨迹关联、墓碑抑制、过期清理
7. 路径询价、归一化成本、竞价/租约仲裁
8. 返回 TaskOutput；协调器将 has_active_task 告诉探索模块
9. 协调器按携弹 > 取弹 > 探索选择导航或抓取原语
10. codec 把本步 task/explore/map 摘要打成下轮广播包并缓存
11. control 返回运动命令；下一仿真周期才发送这个包
```

抓取边缘伪代码：

```text
if carrying_now and not carrying_prev:
    selected = resolve(executing_track or recent_nearest_track)
    selected.status = CARRIED
    cancel_all_own_bids()
    decision = CARRYING
    queue_task_event(CARRY, selected)

elif carrying_prev and not carrying_now:
    if reward_delta > 0:
        selected.status = CLEARED
        create_tombstone(selected, "reward_after_carry")
        decision = RELEASED
        queue_task_event(CLEAR, selected)
    else:
        selected.status = LOST
        create_pending_drop(selected, current_pose)
        decision = LOST
        queue_task_event(DROP, selected)

else:
    track_and_auction_normally()

carrying_prev = carrying_now
```

同一 `update()` 返回时状态和待发事件已经一致；不可先让导航
拿到 `IDLE`，下一步才把 track 改为 `CARRIED`。
如果本机当步 GPS 失效，但携弹仍为真，返航模块使用其自身的
面向传感器/路径退化逻辑，任务分配器不再参与竞拍。

13. 与现有代码的迁移步骤

按方法逐项替换，优先保留现有可运行路径作为回退：

- `_remember_bomb()`：改为把新语义 hit 交
  `BombTrackStore.observe_local()`；旧 list 只在 feature flag 关闭时用。
- `_remove_bomb_memory_near()`：改为按 canonical ID、alias、墓碑
  修订号清理；不得再按 68 像素删除附近所有炸弹。
- `_ingest_peer_messages()`：改为先调用统一 codec，再按事件优先级
  投递给分配器；迁移阶段兼容 v1，避免双方消息互相不可见。
- `_choose_visible_bomb()`：只在 `decision.track_id` 指向本机时，
  从本步 `SemanticHit` 中选与该 track 关联的一条；不得绕过拍卖。
- `_choose_remembered_bomb()`：从 `selected_track`/`NavigationGoal`
  获取世界点，禁止再把第一个 memory 当默认目标。
- `_claimed_by_preferred_peer()`：删除 id 优先逻辑，改为读取
  分配器的 lease/carry 仲裁；feature flag 回退时可保留旧方法。
- `_prune_expired_knowledge()`：由 `TaskAllocator.update()` 的
  peer TTL、track TTL、墓碑保留和 alias 过期统一处理。
- `_mark_current_target_cleared()`：只能在 `reward_delta > 0`
  且前一控制周期实际持弹时调用新 `mark_cleared()`；
  掉落时改为 `PendingDrop`，不能清除。
- `define_message_for_all()`：仅返回协调器上次 `control()`
  已缓存的唯一 v2 dict，不在这里重新读取 GPS 或重新计算竞价。
- `control()`：按第 12 节顺序调协调器；只让赢家追弹，
  携弹优先走现有 `_control_carry()`；没有任务时走探索。

分三次合并更安全：先替换 codec 与消息入口；再把 track store
接入但保留旧目标选择作对照；最后开启成本竞价、关闭旧 claim。
每个阶段都以 `BLUE_TASK_ALLOCATION_ENABLED` feature flag
可回退。共享数据接口需先由五位负责人共同冻结，避免探索方
使用不同 `frame_id`、路径成本单位或消息版本。

15. 性能预算和复杂度

每机每步语义射线最多 35 条；单帧聚类排序约
`O(35 log 35)`。轨迹上限 48，匹配最多 `35*48` 次距离比较；
bid 缓存至多约 480 条，但每步只更新收到的 9 个邻居包和本机
1 条 bid，不做完整二分图求解。竞价选择扫描活动轨迹与有效
邻居报价，约 `O(48*10)`；alias resolve 用路径压缩或有限链缓存。

A* 最贵；每步最多查询 3 个粗排最优候选，路径扩展预算各 500，
只有地图 revision 改变、目标移动超过 20 像素、上一缓存超过
15 步或路线失败时重算。返回成本仅用于竞价，不复制完整路点。
若总计算超过本机目标预算 3 ms，先停额外 A*，使用最近缓存
或几何惩罚回退，仍处理携带/清除硬事件。
3 ms 是工程目标，必须在目标服务器上实测，不是保证值。

消息大小目标低于约 512 字节/步；同一个外层包已被探索与地图
共享，实际序列化大小由测试记录。10 机约每步 10 个包，
不广播完整轨迹或成本向量；debug 分解只写本地内存/日志。

16. 失败模式和退化策略

- GPS 暂时无效：保留 5 步旧世界租约但暂停新 bid；有可靠机体
  语义时允许原赢家近距继续抓取；更久无位姿则释放普通任务。
- GPS 长期无效：只进行 Lidar 安全探索或已携弹返航；不广播
  自称精确的 world 目标。
- A* 暂不可用：成本用惩罚化欧氏估计；执行导航仍用现有
  `_move_toward(..., use_lidar=True)`，进度停滞后释放并冷却。
- 已知 `NO_PATH`：重检一次地图版本再冷却 60 步；不是永久丢弹。
- 未知回收区：`R=0.65`，保持任务可竞拍；发现坐标后重算。
- 两枚弹挨得很近：保留歧义标记，禁止仅凭位置做批量清除；
  需要新角度观测或抓取事件解除歧义。
- 通信中断：每机按自己的局部证据继续工作；lease 超时后
  重新竞拍，日志记录重复追踪，而不是等待不存在的全局中心。
- 重新连通：先 alias 和墓碑，再处理 carry/lease，按总排序
  收敛；执行中的败者主动退让。
- 收到 malformed/超大/旧版消息：解码丢弃单条，控制继续运行。
- 投放失败：无正 reward 时只记 DROP/PendingDrop，重新搜索；
  不能让旧 cleared 广播把炸弹从所有机记忆中抹去。
- 自己被撞毁：不能发 release；邻居 45 步租约超时后接手。
- 两机同时发出相互矛盾的 CLEAR/CARRY：只有带
  `reward_after_carry` 的明确关联证据成为强墓碑；疑似事件
  放入审计日志并要求本地复核，不直接删除目标。

17. 测试与验收标准

17.1 纯算法单元测试

`test_task_allocation.py` 至少覆盖：

1. 同一炸弹多条噪声射线、跨 20 帧和两机消息只形成一条活轨迹。
2. 相距约 35 像素的两枚弹不因链式聚类误合并。
3. 两条重复 track 后期合并，旧 ID bid/lease 经 alias 仍有效。
4. 一个 track 后期分裂为两枚，原租约只绑定其中一支。
5. 最低成本获胜；同成本以较小 id 稳定决胜。
6. 高 epoch 优于低 epoch；旧 seq 不刷新 TTL。
7. 45 步无续租后重新竞价，新 owner 能接手。
8. 真实抓取边缘覆盖普通竞价，携弹机不再对第二枚弹出价。
9. reward 确认生成墓碑；无 reward 掉落不生成墓碑。
10. 墓碑拒绝旧 sighting，且不删除紧邻的第二枚炸弹。
11. 两通信分区各自获胜，重连后按 epoch/cost/id 收敛。
12. GPS、回收点或 A* 缺失时有定义良好的保守输出。
13. 健康值 8 禁投并释放旧普通任务。
14. NaN、错误版本、嵌套超长 ID、缺字段包不抛异常。
15. frame 不同的报价不参与竞价。
16. `define_message_for_all()` 返回的是上一步缓存包；
    不能意外发送本步刚生成但尚未进入发送阶段的内容。

17.2 集成与仿真对照

先用固定两弹 Map01 配置完成冒烟；之后另备只用于本地测试
的不同炸弹布局，不要误把测试布局当比赛真实分布。

- 10 机同时看到一枚：确认只有一个持续赢家；短暂竞价期内
  可允许多个候选，但不应持续一起抓取。
- 10 机同时看到多枚：确认能够形成不同 owner，
  不因同一 id 优先使低编号机包揽全部任务。
- 炸弹在通信半径外：允许局部重复，重连后应退让。
- 切断再恢复通信：重复追踪步数应下降，不能出现无限 epoch 风暴。
- 墙阻挡赢家：应触发冷却和新赢家接手。
- 一机抓取后：邻机收到 CARRY 后在正常消息延迟内停止追踪。
- 在 Map01、Map02 和一张更大地图分别运行；
  同一布局、同一随机种子条件下至少 20 次重复。

与当前 id 优先 baseline 同布局比较，记录每回合：

```text
每弹平均竞争无人机数：每步追同一 canonical ID 的机数的均值
重复追踪步数：同一目标同一步有 >=2 机执行时的机-步总量
分配收敛步数：首次共同可通信至只剩一个 owner 的步数
租约错误释放次数：有效 owner 尚活跃却被非硬事件误释放
目标切换次数：每机任务 ID 发生变化的次数
碰撞与健康损失：每机起始 50 减终值，并记录碰撞相关事件
全部炸弹完成时间：最后一次 verified clear 的逻辑步
官方总分、回收枚数：由现有 launcher 输出，不自行改评分器
```

首版验收门槛建议：无异常运行、无负数/NaN 报价、
强墓碑误清零、同一连通组稳定后持续双赢家为零；
在 20 次配对运行中，平均分不低于当前基础策略，
或在分数持平时重复追踪步数明显下降且健康损失不增加。
这只是工程验收门槛，实际比赛分数仍以官方评测为准。
提交前运行 `pytest` 对应测试和 `./check_submission.sh`；
打包后再用提交检查脚本检查 ZIP 内容与入口。

18. 分阶段实施清单

阶段 A：接口冻结。

   若性能或得分回退，关闭竞价 flag 回到已验证基础策略。
