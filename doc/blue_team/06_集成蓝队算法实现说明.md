蓝队集成算法实现说明

1. 目标与入口

评测入口 `src/swarm_rescue/solutions/my_drone_eval.py` 在 rescue 模式下
返回 `MyDroneBlueAdvanced`；红队入口保持原样。新控制器在原有
`MyDroneBlueBasic` 上增量集成，不修改官方物理碰撞、抓取、评分逻辑。

主要优化方向是：多机尽快分散找弹、减少重复追踪与碰墙，抓弹后沿
已走过的路线安全返航。这里的“优化”是策略设计目标，不代表已经
证明为全局最优或在所有地图取得最高分。

2. 每步控制流程

`MyDroneBlueAdvanced.control()` 先读取 GPS、指南针和里程计，更新
带方差的位姿。每五步用位姿、Lidar 和语义结果更新本机占据栅格。
随后调用基础控制器的状态机，按“携弹返航 > 可见炸弹 > 已记忆
炸弹 > 探索”的顺序决策，最终返回四个执行器命令。

探索使用已知可达的自由栅格与未知栅格的交界作为前沿点。若地图
信息不足、前沿不可达或定位不可靠，退回原有的多机分区蛇形搜索。
前沿候选按本机分区、路程、未知区增益和队友已占用位置评分。
前期约三成无人机承担远端侦察职责：除非炸弹已很近，否则继续
推进到远侧区域；遇到长期没有横向进展的墙体会换向扫查。

发现炸弹后，本机估算“去程 + 返航 + 健康风险 + 定位不确定性 +
切换目标”的代价，并在原有广播中附加报价；多个无人机竞争同一
目标时，优先交给估计代价更小的无人机。通信断开时仍可独立工作。

路径规划仅将已确认自由、满足机体间隙的栅格路线标为安全。使用
有限计算量的 A* 和逐段安全检查压缩折线；未知或被占据区域绝不
被当作已验证捷径。没有可验证路径时仍使用原控制器的局部 Lidar
避障以向新区域推进，因此不能保证完全无碰撞。

抓弹后以探索过程中记录的路点返航；仅在整段走廊已验证安全时
跨越多个路点。接近已观测到的回收区后，交给原有的精确推进和
释放流程。炸弹从机械爪消失不再自动等同于成功处置，只有本步
获得正奖励时才发送“已清除”广播。

针对曾在 Map01 观察到的两机对向堵塞，增加交通协调：携弹机
优先；空载对向相遇时按编号确定让行者，优先向 Lidar 显示开阔
的一侧侧移，必要时后退。里程计显示连续多步没有净位移时启动
短时脱困，同时保持已抓住的炸弹。出生时相邻或同向行驶的无人机
不会仅因靠得近就触发让行。这是局部规则，不能保证任何复杂
拥堵都能解除。

3. 文件分工

- `my_drone_blue_advanced.py`：总状态机接线、广播、健康限速和入口。
- `blue_team/localization.py`：GPS/指南针/里程计融合及异常读数拒绝。
- `blue_team/occupancy_grid.py`：由 Lidar 在线生成三态占据栅格。
- `blue_team/path_planner.py`：已知自由区 A*、间隙检查和路径压缩。
- `blue_team/frontier.py`：分区前沿选择与停滞检测。
- `blue_team/traffic.py`：携弹优先、对向让行与僵持脱困。
- `blue_team/task_allocation.py`：任务代价报价。
- `blue_team/return_path.py`：沿探索轨迹返航及安全捷径。
- `tests/solutions/blue_team/test_advanced_components.py`：核心组件测试。

4. 验证与限制

在项目根目录运行：

```bash
/data/guoyu/miniconda3/envs/swarm/bin/python -m unittest discover -s tests/solutions/blue_team -q
/data/guoyu/miniconda3/envs/swarm/bin/python scripts/check_submission.py
```

完整仿真仍需可用的 X11 显示，例如 MobaXterm 的 X server，或服务器
上的 Xvfb。当前开发会话没有 `DISPLAY`，也没有 `Xvfb` 可执行文件，
因此尚未获得本次拥堵与远端侦察修复版的实际比赛分数；不能声称
已验证更高得分。建议与前次四弹测试对比回收数、健康、越墙时刻
和每轮频率，而不仅比较最终总分。

```bash
python -m swarm_rescue.launcher --competition --stop_at_first_crash \
  -c config/competition_rescue_eval_plan.yml
```

无 GPS 且无指南针时，已初始化的无人机会用里程计短时推算；误差
过大时放弃世界坐标规划，退回局部 Lidar 探索。若从出生起就没有
世界坐标初始化，本实现不会凭空推断全局位姿。后续应在多地图、
多炸弹布局和特殊区域上反复评测，再根据真实分数调节探索分区、
占据阈值、报价权重和返航间隙。
