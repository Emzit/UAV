抓取、投放与远端探索改进
========================

1. 诊断依据

最近一轮 Map01 录制中，0 号炸弹被带到处置区下方，但无人机在右下角
附近反复移动，炸弹始终未接触处置区；1 号炸弹则在接触边界后成功销毁。
右下角炸弹距最近无人机在该轮末约 130 像素。旧远征策略要求看到的炸弹
必须在 70 像素内才接任务，因此远端侦察机可能已经看到目标却不追踪。

2. 抓取改动

近距离追弹改用连续的前进、侧移和小角速度控制，不再要求机头先满足
固定角度阈值才移动；追弹/记忆目标导航时保持抓取命令。随后发现仿真
允许两机抓住同一炸弹，因此现在纯探索时不常开抓取器，并在接近
已被队友抓住的炸弹时关闭抓取器。避让动作不会无故关闭自己的
抓取命令。双机抢弹的处理见下一份说明。

3. 投放改动

处置区语义射线返回的是表面命中点，不是区域中心。旧逻辑只取最近一条
射线，容易朝矩形边角移动；随后固定推进/旋转步数一到就松爪，可能把
炸弹留在区域外。新逻辑使用多条命中射线的中位位置选取边界目标，
靠近后保持抓取并原地旋转，使被关节连接的炸弹扫过边界；若未成功，
下一次选择同一可见边界上的不同位置重试。仿真在炸弹碰到处置区时会
自动销毁它，因此控制器不需要主动松爪。成功清除的判定也从“累计
奖励大于零”改为“本次携弹期间奖励增加”。

4. 探索与计算改动

原先远征侦察机一直忽略 70 像素外的炸弹；现在仅在离出生区较近的
赶路阶段这样做，到远端后恢复正常追踪。远征方向延长至接近远侧
边界，并让更多无人机负责远端；绕过墙后，向前推进的无人机恢复
自己原定的上下分区。已到达或卡住的前沿点附近会短期冷却，减少
在旧区域换相邻目标反复徘徊。

目标竞价只需要比较相对代价，不再为每次竞价运行两次 A*。前沿每次
刷新通常在找到可达目标后最多规划 6 次；若前几次都不可达，最多
尝试 12 个候选点。
普通导航的定期重规划间隔由 18 步增加到 60 步，当前路线的下一段
仍逐步接受安全检查，不安全时会提前触发重规划。

5. 验证与限制

蓝队单元测试、提交检查和语法检查通过。测试覆盖近距侧移
追弹、投放旋转不松爪、远端目标不被 70 像素过滤、竞价不调用 A*、
前沿规划次数上限等。当前执行环境没有 X 显示服务，无法在这里完成
整轮图形仿真；所以尚不能保证四枚炸弹全部回收，必须比较实测结果。

在已有 DISPLAY 的 MobaXterm 会话中使用：

```bash
conda activate swarm
cd /data-ssd/guoyu/uav/baseline/swarm-eod
python -m swarm_rescue.launcher \
  --competition --headless --stop_at_first_crash \
  -c config/competition_rescue_eval_plan.yml
```

优先比较每轮的回收数、执行步数、`frequency` 和健康分。首次比较
不要开启细粒度计时，否则计时本身会增加控制开销。
