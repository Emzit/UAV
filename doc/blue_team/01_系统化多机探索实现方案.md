蓝队系统化多机探索：可实施设计方案
==================================

文档定位：本文件是设计与实施说明，当前仓库尚未实现本文提出的模块。
适用代码基线：`MyDroneBlueBasic` 继承官方 `MyDroneRescueExample`。
主目标：在不读取仿真真值的前提下，提高分散炸弹的发现率，减少重复搜索。

1. 当前代码事实和问题定位

当前蓝方入口位于 `src/swarm_rescue/solutions/my_drone_eval.py`。
`drone_class_for_mode("rescue")` 返回 `MyDroneBlueBasic`。`Map01` 等地图
根据配置创建相应数量的该类实例；每架无人机维护独立的控制器状态。

`my_drone_blue_basic.py` 的 `control()` 按以下顺序处理任务：

```text
读取和合并观测
  -> 携弹返航
  -> 追逐可见炸弹
  -> 前往记忆炸弹
  -> _control_explore()
```

最后的 `_control_explore()` 继承自官方示例，按 90 步直行、28 步转向的
周期运动，并用 Lidar 做局部避障。当前子类仅根据无人机 id 错开周期和
转向符号。它没有显式的“待探索区域”与“已完成区域”。

项目允许的相关接口：

- `measured_gps_position()`：测量位置，像素坐标，可能返回 `None`；
- `measured_compass_angle()`：测量朝向，弧度，可能返回 `None`；
- `lidar_values()`：181 条射线距离，最多 300 像素，可能返回 `None`；
- `lidar_rays_angles()`：与 Lidar 距离一一对应的相对角；
- `semantic_values()`：35 条语义射线的有效检测，最多 200 像素；
- `communicator.received_messages`：本机收到的 `(sender, message)` 列表；
- `size_area`：地图宽高，单位像素，可能为 `None`；
- `identifier`：无人机编号。

墙体不会出现在算法可用的语义检测列表中；建图必须依据 Lidar。
通信半径由 `RANGE_COMMUNICATION = 250` 约束，不能依赖全局广播。
Map04 的面积为 1660 x 1122 像素，是当前内置地图中的最大尺寸。

`GuiSR.on_update()` 先调用每架无人机的 `define_message_for_all()`，再依次
调用 `control()`，随后在 `Playground.step()` 的末尾转发消息。因此：

```text
控制周期 t 更新的探索声明
  -> 控制周期 t+1 才会被 collect_all_messages() 取走
  -> t+1 的 Playground.step() 末尾交付
  -> 接收方通常在 t+2 的 control() 中处理
```

消息不能用于同一步的强一致协调。本文采用租约、确定性仲裁和过期回收。

上述事实可从以下源码直接核对：

```text
solutions/my_drone_blue_basic.py:137      control() 的任务分支
solutions/my_drone_rescue_example.py:241 _control_explore() 的周期运动
simulation/gui_map/gui_sr.py:355         先收消息再调用 control()
simulation/gui_map/gui_sr.py:693         collect_all_messages()
simulation/gui_map/playground.py:356     step() 的物理和消息顺序
simulation/drone/drone_abstract.py:503  measured_gps_position()
simulation/drone/drone_abstract.py:522  measured_compass_angle()
simulation/utils/constants.py:12        Lidar、语义和通信常数
```

2. 方案目标与非目标

目标：

- 第一阶段即使没有占据栅格和 A*，也能进行确定性的分区覆盖；
- 第二阶段由占据栅格提取前沿，按收益、路径代价和队友占用选目标；
- 在有通信时降低重复覆盖，断联时仍能独立探索；
- 只返回结构化探索决策，不直接控制电机；
- 可逐步接入现有蓝方控制器，随时回退到旧探索行为。

非目标：

- 不在本模块实现 Lidar 概率建图和 A* 搜索；
- 不实现炸弹竞价、抓取和回收；
- 不保证断联的多机拥有全局一致地图；
- 在完全没有可信位姿且没有可配准坐标系时，不承诺全图覆盖；
- 不修改官方地图、传感器、碰撞、评分和仿真循环。

4. 每个文件的职责

`blue_team/contracts.py`，共享接口：

- 定义 `WorldPoint`、`PoseEstimate`、`NavigationGoal`、`PathPlan`、
  `ExplorationDecision`、`PeerExploreLease`、`ExplorationInput`；
- 只定义类型和通用值校验，不写探索算法；
- 输入为 Python 基础类型；输出为不可变数据对象；
- 由五模块共同使用，探索负责人只提出必要的增量字段。

`blue_team/config.py`，共享接口：

- 定义只读 `ExplorationConfig` 和特性开关；
- 不读取地图真值或硬编码墙体；
- 由控制器创建一次，传给 `ExplorationManager`。

`blue_team/exploration.py`，本任务主文件：

- 实现公开的 `ExplorationManager` 和内部 `_CoveragePoint`、
  `_FrontierTrack`、`_FrontierCandidate`；
- 管理分区巡航点、前沿快照、目标保持和禁用窗口；
- 输入为 `ExplorationInput` 和占据地图只读视图；
- 输出为 `ExplorationDecision`、租约摘要和调试统计；
- 不调用无人机对象、传感器、通信器和电机命令。

`blue_team/coordinator.py`，共享集成层：

- 确定携弹、取弹、探索的优先级；
- 将探索目标交给 A*，从 `PathPlan` 取下一路点；
- 调用现有 `_move_toward()` 和 Lidar 脱困生成 `CommandsDict`；
- 不能重新实现前沿提取与探索打分。

`blue_team/message_codec.py`，共享通信层：

- 将租约摘要放入唯一的版本化广播包；
- 校验收到的版本、编号、有限坐标和年龄；
- 返回已验证的 `PeerExploreLease` 列表；
- 不选探索目标，不广播整张占据地图。

共享层建议冻结下列公开签名，便于各成员并行实现：

```python
@dataclass(frozen=True)
class ExplorationConfig:
    exploration_enabled: bool = True
    coverage_margin_px: float = 45.0
    coverage_lane_max_spacing_px: float = 160.0
    frontier_refresh_steps: int = 20
    frontier_candidate_cap: int = 12
    lease_ttl_steps: int = 60
    lease_refresh_steps: int = 20
    pose_variance_max_px2: float = 400.0

class BlueMessageCodec:
    def encode(
        self,
        drone_id: int,
        step: int,
        frame_id: str,
        task_payload: Optional[dict],
        explore_payload: Optional[dict],
    ) -> dict: ...

    def decode_exploration(
        self,
        raw_messages: Sequence[Tuple[object, object]],
        local_step: int,
        local_frame_id: str,
    ) -> Tuple[PeerExploreLease, ...]: ...

class BlueCoordinator:
    def navigate_exploration_goal(
        self,
        goal: NavigationGoal,
        pose: PoseEstimate,
        grid: Optional[OccupancyView],
        step: int,
    ) -> PathPlan: ...
```

上面 `Sequence`、`Tuple`、`Optional`、`dataclass` 需要从 `typing` 和
`dataclasses` 导入。`BlueCoordinator` 返回规划结果，再由控制器运动层
转换为 `CommandsDict`；它不能直接把 `PathPlan` 当作电机命令。
其余配置字段见第 13 节，加入数据类时应保持同名和同单位。

`my_drone_blue_basic.py`，现有控制器：

- `__init__` 创建探索管理器和消息缓存；
- `control()` 在炸弹任务之后调用探索模块；
- `define_message_for_all()` 返回上个 `control()` 缓存的消息；
- 保留官方近距追弹、抓取、返航和 Lidar 安全逻辑。

`test_exploration.py` 用合成地图和假规划器检验纯算法；
`test_exploration_integration.py` 用仿真器验证调用链和统计指标。

5. 公共数据契约

以下是建议写入 `contracts.py` 的可执行接口草案。为符合项目声明的
Python 3.8 下限，公开注解使用 `typing.Tuple`、`Optional` 和 `Sequence`。
当前控制器本身使用了 `list[...]`，若实际需要 3.8 运行，仍应单独做兼容
检查；本任务不借机改写其他模块。

```python
from dataclasses import dataclass
from typing import Optional, Tuple

WorldPoint = Tuple[float, float]

@dataclass(frozen=True)
class PoseEstimate:
    position: Optional[WorldPoint]
    heading: Optional[float]
    position_variance: float
    heading_variance: float
    source: str
    frame_id: str
    step: int
    valid: bool

@dataclass(frozen=True)
class NavigationGoal:
    goal_id: str
    kind: str
    position: WorldPoint
    tolerance: float
    priority: float
    created_step: int

@dataclass(frozen=True)
class PathPlan:
    status: str
    waypoints: Tuple[WorldPoint, ...]
    total_cost: float
    map_revision: int
    created_step: int
    reason: str

@dataclass(frozen=True)
class ExplorationDecision:
    status: str
    goal: Optional[NavigationGoal]
    frontier_id: Optional[str]
    expected_gain: float
    estimated_cost: float
    lease_until_step: int
    reason: str

@dataclass(frozen=True)
class PeerExploreLease:
    peer_id: int
    frontier_id: str
    center: WorldPoint
    bid: float
    frame_id: str
    team_size: int
    epoch: int
    sender_step: int
    received_step: int
    expires_step: int

@dataclass(frozen=True)
class ExplorationInput:
    pose: PoseEstimate
    step: int
    world_size: Optional[WorldPoint]
    drone_id: int
    drone_count: Optional[int]
    has_bomb_task: bool
    carrying: bool
    peer_leases: Tuple[PeerExploreLease, ...]
```

约定：

- `WorldPoint` 的 x、y 单位为世界像素；原点在画布中心；
- `heading` 单位为弧度，导航计算前归一化到 `[-pi, pi]`；
- `position_variance` 单位为像素平方，
  `heading_variance` 单位为弧度平方；未知方差用 `float("inf")`；
- `PoseEstimate.valid` 表示 `position`、`heading`、`frame_id` 和方差均
  满足定位模块的基本约束；`position is None` 只表示本步没有可用坐标；
  一个有上次位置但方差过大的估计可以 position 非空且 valid=False；
- `PoseEstimate.source` 建议为 `GPS_FUSED`、`ODOM_COMPASS_FUSED`、
  `DEAD_RECKONING`、`LOCAL_ONLY`、`UNINITIALIZED` 之一；最终枚举
  由定位负责人定稿；
- `frame_id` 建议为 `world` 或 `local:d<ID>:e<EPOCH>`；仅相同 frame
  的目标、租约和地图可以直接比较；
- `PoseEstimate.step`、`created_step`、`received_step` 都是仿真逻辑步数；
- `NavigationGoal.kind` 在本任务仅取 `EXPLORE_COVERAGE`、
  `EXPLORE_FRONTIER`；
- `NavigationGoal.priority` 是 0 到 1 的模块内优先级；携弹和取弹
  始终由协调器置于探索之前；
- `PathPlan.status` 至少支持 `READY`、`AT_GOAL`、`NO_PATH`、
  `BUDGET_EXCEEDED`、`STALE_MAP`、`NO_POSE`；
- `ExplorationDecision.status` 仅取 `ACTIVE`、`HOLD`、`SUSPENDED`、
  `LOCAL_FALLBACK`、`EXHAUSTED`；
- `expected_gain`、`estimated_cost` 是 0 到 1 的归一化指标，
  无估计时用 1.0 作为保守代价；
- `lease_until_step` 是本机租约到期步数；无声明时为 -1；
- `goal` 为 `None` 时协调器绝不调用 A*；
- 所有广播坐标必须有限；JSON 风格消息中不发送 `inf` 或 `nan`。

探索状态的含义：

```text
ACTIVE         已选定可到达的探索目标
HOLD           暂无更好目标，保持当前安全位置或短暂停顿
SUSPENDED      携弹或执行炸弹任务，探索租约已释放
LOCAL_FALLBACK 无可靠世界坐标，仅允许局部避障式搜索
EXHAUSTED      本地图中没有有价值、可到达的候选
```

不要把 `EXHAUSTED` 等同于“地图所有炸弹已发现”。传感器遮挡和地图错误
都可能产生假完成；每隔一段时间要重新审视该状态。

6. 输入契约

`ExplorationManager.update()` 每控制周期只调用一次。数据由协调器组装：

- `PoseEstimate`：定位模块创建，不可变；本模块只读。若 step 比当前慢
  超过 2 步，停止世界坐标目标选择；
- 占据地图只读视图：地图模块创建，暴露 `revision`、`resolution`、
  `frame_id`、`state_at(row, col)` 等查询；本模块不得修改栅格；
- 路径代价查询：规划模块创建，返回状态、长度和 map revision；
  查询失败时仅允许有边界的几何成本估计，不把未验证捷径当安全路径；
- 炸弹任务状态：任务分配模块提供 `has_bomb_task` 和 `carrying`；
  只读，任一为 True 时释放探索租约；
- 队友租约：通信层验证并转成 `PeerExploreLease`；
  只读，过期或 frame 不同的条目直接丢弃；
- 地图宽高 `world_size=(W, H)`：由 `size_area` 传入，单位像素；
  未知或非正数时不生成全局巡航点；
- `drone_id`、`drone_count`：来自控制器 identifier 和 MiscData；
  后者缺失时暂按 1 台本机规划，恢复后重建分区；
- `step`：由协调器传入的单调逻辑步数，不依赖墙钟秒数。

建议只读地图与路径服务使用 `typing.Protocol`，签名为：

```python
class OccupancyView(Protocol):
    revision: int
    resolution: float
    frame_id: str
    width: int
    height: int

    def state_at(self, row: int, col: int) -> int: ...
    def world_to_cell(self, point: WorldPoint) -> Optional[Tuple[int, int]]: ...
    def cell_center(self, row: int, col: int) -> WorldPoint: ...
    def unknown_count(self, center: WorldPoint, radius: float) -> int: ...
    def risk_near(self, center: WorldPoint, radius: float) -> float: ...

class RouteCostProvider(Protocol):
    def estimate_cost(
        self,
        start: WorldPoint,
        goal: WorldPoint,
        max_expansions: int,
    ) -> Tuple[str, float, int]: ...
```

`state_at()` 返回 `-1=UNKNOWN`、`0=FREE`、`1=OCCUPIED`；越界须抛
`IndexError`，由本模块在访问前检查边界。`risk_near()` 返回 0 到 1。
`estimate_cost()` 返回 `(status, path_length_pixels, map_revision)`；
`NO_PATH` 与预算耗尽必须区分。若规划模块采用携弹参数，探索固定传 False。

7. 输出契约

公开接口建议为：

```python
class ExplorationManager:
    def __init__(self, config: ExplorationConfig) -> None: ...

    def update(
        self,
        data: ExplorationInput,
        grid: Optional[OccupancyView],
        routes: Optional[RouteCostProvider],
    ) -> ExplorationDecision: ...

    def lease_payload(self) -> Optional[dict]: ...
    def debug_snapshot(self) -> dict: ...
    def invalidate_route(self, goal_id: str, step: int) -> None: ...
    def reset(self, world_size: Optional[WorldPoint]) -> None: ...
```

`update()` 返回给协调器；其中 `goal` 交给路径规划器。
协调器读取 `PathPlan.waypoints`，选择下一路点，并转成运动命令。
`lease_payload()` 给消息编码层，返回基础类型的紧凑字典。
`debug_snapshot()` 只写本地日志，不进入正常通信包。
`invalidate_route()` 在规划器报告当前目标不可达时调用。

示例返回值：

```python
ExplorationDecision(
    status="ACTIVE",
    goal=NavigationGoal(
        goal_id="frontier:world:d6:14",
        kind="EXPLORE_FRONTIER",
        position=(184.0, -96.0),
        tolerance=24.0,
        priority=0.72,
        created_step=430,
    ),
    frontier_id="frontier:world:d6:14",
    expected_gain=0.81,
    estimated_cost=0.34,
    lease_until_step=490,
    reason="highest_normalized_utility",
)
```

本模块不返回 `forward`、`lateral`、`rotation` 或 `grasper`。

8. 基础覆盖算法

8.1 选择与初始化

选择“编号分区 + 每区双纵向巡航线 + 蛇形访问”。比按无人机 id
仅改变转向方向更可重复；不依赖占据地图，可以先单独落地。

给定世界宽高 `(W, H)`、有效无人机数量 N：

```text
margin = 45 px
usable_w = W - 2 * margin
usable_h = H - 2 * margin
strip_width = usable_w / N
strip_left(i) = -W / 2 + margin + i * strip_width
lane_count = max(2, ceil(strip_width / 160))
lane_x(i, j) = strip_left(i) + strip_width * (j + 0.5) / lane_count
j = 0, ..., lane_count - 1
y_low = -H / 2 + margin
y_high = H / 2 - margin
```

每个 lane 各有低、高端点，按纵向相反方向交替访问，形成蛇形路线。
入口选与本机位置更近的一端，避免固定从地图下边开始。
在 Map01、N=10 时，`strip_width=116` 像素且 `lane_count=2`。
N=1 或 N 较少时公式自动增加 lane 数，保证 lane 间距不超过
160 像素。200 像素语义量程在无遮挡情况下足以覆盖条带，
但墙体遮挡仍须靠地图前沿探索补齐。

代码不假设无人机一定出生在分区内。

若 `N` 不可用，采用本机单机网格；当 N 恢复或显著变化时重建目标队列，
保留已访问点集合。队友暂时失联不改变静态 id 分区；连续 120 步无任何
邻居且本区无可达目标时，才将相邻空闲条带列为低优先级候选。
这避免因为局部通信断开就让所有无人机同时重新分区。

8.2 巡航点状态

每个 waypoint 状态为 `PENDING`、`ACTIVE`、`VISITED`、
`BLOCKED_UNTIL`。位置在目标半径 30 像素内连续 3 帧即完成。
若连续 45 步进度不足 10 像素或 A* 返回 `NO_PATH`，本点先标为
`BLOCKED_UNTIL=step+120`，然后尝试下一个点；不可永久删除。
若已知占据栅格显示目标被墙占据，在 40 像素内搜索最近可行替代点；
替代点也不可达则进入禁用窗口。

基础覆盖管理器只选目的地。导航优先由 A* 执行；尚无 A* 时使用
现有 `_move_toward(..., use_lidar=True)` 和脱困逻辑。该局部导航未必能
绕过长墙，达到进度超时后必须换目标，不能永远撞墙。

8.3 无 GPS 的退化

有最近可信世界位姿且方差未越过导航阈值时，短暂 GPS 中断可继续原目标。
当 position 为 `None`、frame 不匹配或方差过大时，返回：

```python
ExplorationDecision(
    status="LOCAL_FALLBACK",
    goal=None,
    frontier_id=None,
    expected_gain=0.0,
    estimated_cost=1.0,
    lease_until_step=-1,
    reason="no_reliable_world_pose",
)
```

协调器调用现有局部 Lidar 避障探索，前方阻挡时按 `(drone_id +
retry_count) % 2` 选择旋转方向。此时不声称已覆盖世界坐标格。
定位模块后来提供可信 `world` frame 位姿时，恢复原巡航进度。

9. 前沿探索算法

9.1 可用条件

前沿模式须同时满足：地图视图存在、尺寸和分辨率有效、地图 frame 与
位姿 frame 相同、位姿方差不超过 400 px^2、地图已有至少 20 个已知
自由格、规划器可用。阈值是初始建议，须由测试调优。

由于地图负责人负责 Lidar 投影，本模块只从其三态只读视图提取前沿。
推荐栅格分辨率 20 像素：Map04 约 83 x 57，即约 4731 格。

9.2 提取和聚类

一个自由格如果 4 邻域中存在未知格，就是候选前沿格。先从本机所在的
已知自由格做可达性泛洪，仅保留连通可达的自由格。前沿格按 8 邻接
进行聚类，过滤少于 3 格的簇和膨胀障碍附近的不安全簇。

每簇代表目标不能简单选算术中心，因为中心可能位于障碍或未知格。
从簇中选择“与本机路径成本小、邻近未知格多、离已知障碍较远”的
自由格代表点。最多保留得分粗排前 12 个簇做精确路线询价。

伪代码：

```text
if grid.revision == cached_revision and step - last_refresh < 20:
    use_cached_candidates()
else:
    reachable_free = flood_from_pose_on_known_free(grid)
    frontier_cells = free_with_unknown_neighbor(reachable_free)
    clusters = connected_components(frontier_cells, adjacency=8)
    clusters = reject_small_or_unsafe(clusters)
    match_clusters_to_previous_tracks(clusters)
    candidates = rough_rank(clusters)[:12]
    refresh_candidate_cache(candidates, grid.revision, step)
```

9.3 稳定 frontier_id

不能把地图 revision 或当前质心直接放进永久 id；地图更新会让同一前沿
的边界和质心抖动。本机维护 `FrontierTrack`：

- 每次聚类后，以同 frame 的前次簇做匹配；
- 栅格交并比至少 0.25，或代表点距离小于 60 像素且未知边界重叠；
- 一对一匹配先按最大重叠、再按最小距离；
- 匹配成功继承旧 id；新簇生成 `frontier:<frame>:d<id>:<counter>`；
- 合并时保留创建步更早的 id，并给旧 id 保留 60 步别名；
- 分裂时最大子簇继承旧 id，其余生成新 id；
- 消失超过 40 步的 track 删除。

不同无人机不会生成相同 id，因此跨机判断采用 frame 一致、代表点距离
小于 100 像素或粗栅格区域重叠。`frontier_id` 仅作为来源可追溯标识，
不是跨机相等判定的唯一依据。

9.4 收益与代价

对每个前沿候选，在半径 200 像素范围统计尚未知且潜在可观测的单元。
同一未知区域若已被本机最近 80 步访问轨迹覆盖，应降低收益；
已被队友有效租约覆盖的区域另计重叠惩罚。

建议初版归一化：

```text
gain = min(1, unknown_count / 180)
cost = min(1, estimated_path_length / max(W, H))
overlap = max(peer_coverage_overlap) 或 0
risk = grid.risk_near(candidate, 50)
switch = 0 若保持当前目标，否则 1

score = 0.45 * gain
      - 0.25 * cost
      - 0.20 * overlap
      - 0.10 * risk
      - 0.08 * switch
```

所有子项均在 0 到 1。`unknown_count` 分母 180 对应约 20 像素栅格的
较大可观测区域，是需要实测调优的初值。

`peer_coverage_overlap` 可定义为候选目标到队友声明中心的归一化距离：

```text
overlap = max(0, 1 - distance(candidate, peer_center) / 150)
```

无路可达候选不参与评分；`BUDGET_EXCEEDED` 时允许用直线距离作为排序
近似，但后续不得把该目标标为可执行，直到规划器确认路径。当前目标
有 0.08 的保持优势。新目标必须比旧目标高至少 0.12，或旧目标已失效，
才触发切换。这样降低传感器噪声造成的频繁反复。

9.5 更新与终止

以下事件立即检查当前目标：

- 到达目标 30 像素范围并持续 3 步；
- 所在前沿消失或信息收益低于 0.05；
- 规划器返回 `NO_PATH`、`STALE_MAP` 或路点被占据；
- 连续 45 步无前进；
- 位姿 frame 改变或方差超限；
- 炸弹任务成为更高优先级任务。

到达后将附近自由区域记为最近已访问，不直接将未知格改写为自由格；
未知、自由和占据只由建图模块维护。

10. 多机租约和消息格式

10.1 租约

本机选定前沿后发送租约，期限 60 控制步，每 20 步续约。
接收端根据本地 `received_step` 计算过期时间：

```text
expires_step = received_step + min(advertised_ttl, 60)
```

不要直接信任发送端的绝对步数。发送端 step 只用于去重和拒绝旧消息。
租约到期、主动释放或 frame 变化后，前沿重新成为可选目标。

同时声明相近前沿时使用可比较的出价。由于前述 score 的理论范围为
`[-0.63, 0.45]`，先映射到 0 到 100，再以 5 分为一档处理近似平局：

```text
bid = round(100 * clamp((score + 0.63) / 1.08, 0, 1))
bid_bucket = bid // 5
shared_epoch = min(local_lease_epoch, peer_lease_epoch)
fair_rank = (drone_id - shared_epoch) mod N
winner_key = (-bid_bucket, fair_rank, drone_id)
```

`winner_key` 按字典序最小获胜。每条租约的 epoch 在选定目标时设为
`floor(step / 200)`，续租时保持不变，并在消息中发送。双方对同一对
租约都计算相同的 `shared_epoch`。出价档优先，公平轮转只用于同档。
双方公布的 N 不一致或任一方未知时，改为
`winner_key=(-bid_bucket, drone_id)`。接收方不能采用依赖本机私有信息
的平局规则，否则可能产生相反的胜者。

本地对冲突双方的出价落在同一 5 分档时视为近似平局；收到租约后
释放败者目标。通信分区期间可能重复探索；重新相遇后按租约仲裁，
败者转向下一个前沿。不要为追求无法实现的全局一致性而停止搜索。

10.2 广播包

每架无人机每步只能返回一条广播消息，因此探索信息是统一消息的一部分。
建议外层使用 Python 基础类型：

```python
{
    "kind": "blue-team-v2",
    "v": 2,
    "id": 6,
    "step": 430,
    "n": 10,
    "frame": "world",
    "task": {"mode": "explore", "claim": None},
    "explore": {
        "fid": "frontier:world:d6:14",
        "x": 184.0,
        "y": -96.0,
        "bid": 72,
        "epoch": 2,
        "ttl": 60,
        "seq": 8
    },
    "map": None
}
```

消息中的 `task` 由任务分配负责人定义；此处仅表示占位。
一个包最多包含 1 条探索租约，不放入完整轨迹、完整地图和 dataclass。
坐标可四舍五入到 1 像素，发送和接收时检查有限数、地图边界、id
范围、版本、队伍人数、epoch 及 `ttl` 上限。不同 frame 的探索声明
只作诊断，不参与竞争。

接收端记录 `last_seq`，丢弃相同发送者的旧 seq。重复包不延长租约。
短暂丢包不会立即释放租约；超过 60 步未收到续租时自动释放。

10.3 与旧版消息的迁移

目前广播包使用 `kind="blue-basic-v1"`，含炸弹 `claim`、`sighting`、
`cleared` 等字段。若只有探索负责人先提交代码，新的 codec 应同时
解析 v1 炸弹字段和 v2 探索字段；新版发送包也暂保留旧字段，直到
任务分配模块迁移完毕。切换发送端的 `kind` 之前，必须先让
`_ingest_peer_messages()` 接受 v2 并继续解析旧炸弹字段；仅保留字段但
改变 `kind` 仍会让原方法丢弃整条消息。

11. 单步调用时序

稳态控制周期建议如下：

```text
上一周期末已缓存广播包
  -> GuiSR.collect_all_messages() 读取缓存
  -> 本轮 control() 获取新传感器帧
  -> 定位模块产生同一步 PoseEstimate
  -> 地图模块更新只读地图和 revision
  -> 消息解码层读取上次物理步交付的队友消息
  -> 炸弹任务分配器更新
  -> 若 carrying/追弹/记忆取弹，暂停探索租约并执行对应任务
  -> 否则 ExplorationManager.update() 返回 ExplorationDecision
  -> 协调器向路径规划器请求 PathPlan
  -> 局部运动层叠加 Lidar 避障，返回 CommandsDict
  -> 更新下一周期的广播包缓存
  -> Playground.step() 执行运动并交付本轮先前收集的消息
```

消息缓存初始化为合法空包。`define_message_for_all()` 只返回缓存的浅拷贝，
不进行传感器读取、前沿聚类或竞价。因为该方法在 `control()` 前执行，
它读到的必然是上一控制周期状态；文档中的 TTL 已考虑传播延迟。

12. 与现有控制器的迁移步骤

建议控制器仅在原本落入 `_control_explore(cmd)` 的分支接入新探索逻辑：

```python
if carrying:
    manager.suspend(step)
    return self._control_carry(cmd)

if visible_target is not None:
    manager.suspend(step)
    return self._control_chase_bomb(cmd, visible_target)

if self._target_bomb is not None:
    manager.suspend(step)
    return self._control_to_remembered_bomb(cmd)

decision = manager.update(inputs, grid, routes)
if decision.status == "LOCAL_FALLBACK":
    return super()._control_explore(cmd)
if decision.goal is None:
    return safe_hold_or_scan(cmd)
return coordinator.navigate_exploration_goal(decision.goal, cmd)
```

该代码是接入伪代码，`manager`、`inputs` 和 `coordinator` 必须先在
`__init__` 中创建，并对消息缓存、地图视图和定位估计做真实接线。

字段归属：

- 保留 `_target_bomb`、`_bomb_memories`、`_peer_claims`、
  `_known_disposal`、`_breadcrumbs`、`_return_waypoints`；
- 将 `_explore_tick`、`_explore_offset`、`_preferred_turn_sign` 的探索
  专用状态转移到 `ExplorationManager`；现有父类局部回退使用时可暂留；
- 新增 `_exploration`、`_message_cache`、`_last_explore_decision`；
- 只在协调器落实了 PathPlan 的 `READY/AT_GOAL/NO_PATH` 处理后，
  才用前沿目标替换父类周期探索。

路径可用时取第一个未到达 waypoint，用现有 `_move_toward(...,
use_lidar=True)`。若 `NO_PATH`，调用 `invalidate_route()`，暂禁该目标，
再选次优前沿；若局部 Lidar 连续阻挡，由现有 `_run_lidar_escape_if_needed()`
执行后退和转向。运动层确保输出四个键且命令在允许范围内。

配置开关 `exploration_enabled=False` 时，完全回到现有
`_control_explore(cmd)`，用于回归测试和紧急回滚。

14. 复杂度和性能预算

Map04 若栅格分辨率为 20 像素，约为 83 x 57 = 4731 格。
每架无人机只维护自己的本地地图和当前前沿缓存。

- 每步维护当前目标、租约、进度：O(P + 1)，P 为收到的邻机数量，
  且只在通信范围内；
- 每 20 步提取可达自由格和前沿：O(C)，C <= 4731；
- 聚类：O(F)，F 为当前前沿格数，F <= C；
- 最多 12 个候选各统计半径 200 像素未知格，约 12 x 314 次
  单元检查，即约 3800 次；
- 路径代价查询每轮最多 4 个候选，单次预算 800 扩展节点；
- 维护前沿 track 和队友租约：通常几十条，内存远小于占据地图。

按 10 机估算，前沿扫描最坏约 10 x 4731 / 20 = 2366 格/控制步的
摊销量；实际各机刷新分散在不同步，可以用 `drone_id % 20` 错峰。
不可每步扫描 1660 x 1122 原始像素，也不可每步对全部前沿执行 A*。

建议将单次前沿刷新目标控制在 10 ms 内，单步探索管理器通常低于
1 ms。这是开发目标，不是已实测结果。必须在服务器实际计时后调整
刷新步数、候选上限和规划预算。

15. 降级策略和失败模式

- 地图未建立：执行编号分区覆盖；
- 地图与位姿 frame 不一致：冻结前沿选择，使用可信世界位姿下的覆盖；
- 路径预算耗尽：保持当前安全目标，推迟精确查询；不把直线当通路；
- 所有前沿不可达：退回尚未访问的分区巡航点；
- 巡航点连续阻挡：进入 120 步禁用窗口，改用其他点；
- GPS 暂时失效但融合位姿仍可信：保持现有目标，不频繁重选；
- 位姿失效：释放世界坐标租约，仅保留局部 Lidar 探索；
- Lidar 也失效：停止平移、低速原地扫描，并等待传感器恢复；
- 通信失效：按本机地图独立探索；
- 旧消息、异构版本、NaN 坐标：丢弃，不影响本机决策；
- 分区重新连通：按 bid 和公平平局规则解决冲突；
- 被炸弹任务打断：立即释放探索租约；任务结束后重新评估；
- 当前地图显示 `EXHAUSTED`：每 100 步重查一次并优先访问
  最近一次未确认的遮挡区域，不能直接停止全部无人机。

16.2 集成测试

- 目标切换次数；
- 无法到达目标后切换或回退所需步数；
- 墙体碰撞数、健康损失；
- 每步探索计算时间和单次刷新耗时。

建议首轮验收门槛：

```text
20 回合中控制器异常次数 = 0
目标卡死超过 120 步次数 = 0
同等 500 步下重复覆盖比例降低 >= 20%
首次发现炸弹的中位步数降低 >= 15%

```

17. 分阶段实施清单

阶段 A，接口冻结：

1. 与定位、建图、路径和任务分配负责人定稿 `contracts.py`；
2. 统一世界坐标、frame_id、状态值、消息版本和租约 TTL；
3. 用假地图和假路径查询器写探索模块单元测试。

阶段 B，独立覆盖：

1. 实现编号条带和蛇形巡航点；
2. 只在现有探索分支接入，保留 `exploration_enabled` 开关；
3. 用旧的 Lidar 局部导航跟踪巡航点；
4. 检查是否避免全队从出生点朝同一方向运动。

阶段 C，地图前沿：

1. 接入地图只读视图；
2. 实现可达自由格提取、前沿聚类和稳定 track；
3. 实现收益、代价和风险评分；
4. 接入 A* 路径查询，保留局部 Lidar 安全层。

阶段 D，多机租约：

1. 把探索字段加入唯一广播包；
2. 完成消息校验、TTL、冲突仲裁和断联恢复；
3. 确认旧炸弹消息不会因版本迁移丢失。

阶段 E，批量评测：

1. Map01、Map02、Map04 做配对多回合比较；
2. 检查发现率、回收率、碰撞、平均分和耗时；
3. 若收益不稳定，先回退前沿模式，仅保留分区覆盖；
4. 最终运行 `./check_submission.sh` 和提交 ZIP 检查。

18. 尚需确认的问题

这些问题不会阻止阶段 A 和 B 开工，但应在跨模块接口冻结前解决：

1. 最终占据栅格分辨率是否采用 20 像素？若不同，前沿最小簇格数和
   信息收益归一化必须同步调整。
2. 定位模块在 GPS 失效时是否仍能输出 `world` frame 的可信位姿？
   若只能输出 `local:*`，本机地图和探索目标是否一并变换？
3. A* 成本接口的单位是路径像素、时间步数还是风险加权成本？
   本文评分暂按路径像素计算。
4. 任务分配模块的统一广播包何时启用 v2？迁移期需要兼容多久 v1？
5. 多机地图是否共享稀疏补丁？若共享，前沿 track 与 map revision
   的更新频率可能变化。
6. 评测器是否允许固定随机种子？若不允许，使用相同布局的多回合
   统计和置信区间比较。

文件；文中的默认参数和性能目标需要在真实服务器和官方仿真中验证。
