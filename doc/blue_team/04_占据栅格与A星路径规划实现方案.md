蓝队占据栅格与 A* 路径规划实现方案
=================================

文档性质：面向编码和联调的设计稿；当前 baseline 尚未实现本模块。
目标目录：`src/swarm_rescue/solutions/blue_team/`。
本方案与 01 探索、02 目标分配、03 返航方案共享数据契约。

1. 当前代码事实和问题

已阅读并核对：

  但没有持续地图或全局路径搜索。

- `simulation/drone/drone_sensors.py`：GPS 和指南针使用带时间

- `simulation/elements/normal_wall.py`：墙有物理厚度；只能用于

- `simulation/utils/constants.py`：Lidar、语义与通信范围。
- `simulation/utils/misc_data.py`：`size_area`、回合步数等元数据。
- `submission_check.py`：检查提交源码，禁止部分真值调用/状态读取。

Map01 至 Map05 的 `(size_area, max_timestep_limit)` 分别为：

```text
Map01  (1250, 800),  2000 步
Map02  (1200, 900),  5000 步
Map03  (1113, 750),  5000 步
Map04  (1660, 1122), 5000 步
Map05  (1200, 1200), 7200 步
```

这些值仅用于估算内存与测试规模。算法从 `size_area` 获取运行
时尺寸，不硬编码任何一张地图的墙坐标或回收区坐标。
当前局部 Lidar 能在正前方减速、转向、脱困，但无法记住远处长墙；
几何直线到炸弹或回收区很可能反复撞墙。

2. 目标与非目标

目标：

1. 把测量 Lidar + 统一 `PoseEstimate` 转成逐步更新的三态地图。
2. 分离持久静态障碍、短暂动态障碍与未知区域。
3. 提供空载/携弹两套保守安全间距及只读查询接口。
4. 给探索模块前沿信息基础，给竞价模块实际路径长度，
   给返航模块安全线段检查，给协调器可执行 A* 路线。
5. 计算和内存有明确上界；失败时回到现有 Lidar 安全层。

非目标：不读取地图 PNG/JSON 的真实墙体、不做依赖 ROS/SciPy
的完整 SLAM、不保证动态无人机未来轨迹、不输出机械爪和电机命令；
不因 A* 规划成功就删除现有实时 Lidar 避障。

5. 数据契约

统一公开类型使用 Python 3.8 可接受的 `typing.Tuple` 等标注。

```python
from dataclasses import dataclass, field
from typing import Optional, Protocol, Tuple

WorldPoint = Tuple[float, float]
GridCell = Tuple[int, int]               # row, col

class GridQueryProtocol(Protocol):
    def state_at(self, row: int, col: int,
                 revision: int) -> int: ...
    def world_to_cell(self, point: WorldPoint) -> Optional[GridCell]: ...
    def cell_center(self, row: int, col: int) -> WorldPoint: ...
    def unknown_count(self, center: WorldPoint, radius: float,
                      revision: int) -> int: ...
    def risk_near(self, center: WorldPoint, radius: float,
                  revision: int) -> float: ...

@dataclass(frozen=True)
class PoseEstimate:
    position: Optional[WorldPoint]
    heading: Optional[float]
    position_variance: float             # px^2
    heading_variance: float              # rad^2
    source: str
    frame_id: str
    step: int
    valid: bool

@dataclass(frozen=True)
class OccupancyGridView:
    revision: int
    resolution: float                    # px/cell
    width: int                           # cols
    height: int                          # rows
    origin: WorldPoint                   # (-W/2, -H/2)
    updated_step: int
    pose_frame_id: str
    _query: GridQueryProtocol = field(repr=False, compare=False)

    def state_at(self, row: int, col: int) -> int: ...
    def world_to_cell(self, point: WorldPoint) -> Optional[GridCell]: ...
    def cell_center(self, row: int, col: int) -> WorldPoint: ...
    def unknown_count(self, center: WorldPoint, radius: float) -> int: ...
    def risk_near(self, center: WorldPoint, radius: float) -> float: ...

@dataclass(frozen=True)
class NavigationGoal:
    goal_id: str
    kind: str
    position: WorldPoint
    tolerance: float                     # px
    priority: float                      # [0,1]
    created_step: int

@dataclass(frozen=True)
class PathPlan:
    status: str
    waypoints: Tuple[WorldPoint, ...]    # 不含当前起点
    total_cost: float                    # 含风险的 px-equivalent
    map_revision: int
    created_step: int
    reason: str
    geometric_length_px: float = 0.0
    clearance_px: float = 0.0
    goal_id: str = ""

@dataclass(frozen=True)
class SegmentCheck:
    status: str                          # SAFE/BLOCKED/UNKNOWN/STALE
    min_clearance: float                 # px；未知为 -1
    checked_cells: int
    map_revision: int
    reason: str

@dataclass(frozen=True)
class SemanticObservation:
    angle: float                         # 机体系 rad
    distance: float                      # px
    entity_type: str                     # DRONE/BOMB/DISPOSAL_CENTER/OTHER
    grasped: bool

@dataclass(frozen=True)
class GridUpdateStats:
    valid_rays: int
    free_cells_touched: int
    static_hits_confirmed: int
    dynamic_hits: int
    revision_changed: bool
    reason: str
```

`OccupancyGridView._query` 是隐藏实现引用，不是可写 ndarray；
冻结数据类只能防字段重新赋值，不能自动冻结其引用对象。
每个查询方法都把视图的 `revision` 传给 `GridQueryService`；
若内部版本变化，应抛可识别 `StaleViewError`，调用方重新取
`view()`，不能默默用新地图回答旧版本证书。单线程控制周期
按“建图完成后再查询”执行，避免无谓拷贝整张栅格。

`state_at()` 返回 `-1=UNKNOWN`、`0=FREE`、`1=OCCUPIED`；
越界抛 `IndexError`。未知不是自由，暂时动态层单独查询。
`check_segment()` 遇近期动态层硬阻挡时也返回 `BLOCKED`，
但 `reason="dynamic_recent"` 且不改静态三态；返航模块
可等待或局部绕行，不把它当永久墙。
`PathPlan.status` 完整集合：

```text
READY              有经过地图约束的可执行 waypoint
AT_GOAL            已在目标容差内；waypoints=()
NO_POSE            位姿缺失、过期或 frame 不符
GOAL_OUT_OF_BOUNDS 目标在画布外
START_BLOCKED      起点附近无法找到安全自由格
GOAL_BLOCKED       目标容差内无可用自由格
NO_PATH            本次已知自由图里找不到连通路线
BUDGET_EXCEEDED    扩展/时间预算耗尽；不返回未经证实的完整路线
STALE_MAP          搜索中或复用时地图版本变化
DEGRADED_DIRECT    只给局部反应式退化建议，不是安全全局路径
```

`DEGRADED_DIRECT` 默认 `waypoints=()`，`reason` 说明局部候选；
协调器不得把它当成 `READY` 或朝目标穿墙直行。
`AT_GOAL` 并不表示炸弹被抓或投放成功。
失败状态 `total_cost=inf`、`geometric_length_px=inf` 只在本机
Python 对象使用，若发消息必须转为有限状态码，不能广播 inf。

6. 坐标系和转换公式

统一世界坐标 x 向右、y 向上，原点在画布中心。
栅格 col 向右、row 向上；数组访问固定 `[row, col]`。
地图左下世界边界为 `origin=(-W/2, -H/2)`。
推荐分辨率 `r=20 px/cell`：

```text
cols = ceil(W / r)
rows = ceil(H / r)
col = floor((x + W/2) / r)
row = floor((y + H/2) / r)
```

有效世界范围为 `-W/2 <= x < W/2`、`-H/2 <= y < H/2`。
左/下界恰好等于负半宽/高时属于第 0 格；右/上界恰好等于
正半宽/高时越界，不能夹进最后一格。对非常靠近正边界的
浮点误差，可在传感器射线截断阶段使用向内 `1e-6 px`
的端点；公共 `world_to_cell()` 不暗中容忍真正越界的目标。

`grid_to_world(row,col)` 返回“单元与真实画布交集的中心”：

```text
x0 = -W/2 + col*r
x1 = min(W/2, x0+r)
y0 = -H/2 + row*r
y1 = min(H/2, y0+r)
center = ((x0+x1)/2, (y0+y1)/2)
```

这避免 Map03 等尺寸不能被 20 整除时，最后一行/列中心落在
画布外。转回来必得原 `(row,col)`；任意原点经过
`world_to_cell -> cell_center` 的每轴误差最多 10 px，
最后一个残格误差更小。`NaN/inf` 坐标返回 None；
超出边界返回 None。线段出画布时先按半开矩形裁剪，
命中画布边界不可写成“有墙的 Lidar 终点”，除非传感器
真的给出墙命中证据。

示例 Map04：`W=1660,H=1122,r=20`，
`cols=83, rows=57`，共 4731 格。`(-830,-561)` 属于 `(0,0)`；
`(830,0)` 越界；最后一行的中心 y=560，不是 569。

7. Lidar 地图更新

7.1 一帧输入校验与时间同步

`lidar_values()` 预期 shape `(181,)`，`lidar_rays_angles()`
同形状，角度为机体系 rad。语义列表最多来自 35 条射线，
只用 `angle/distance/entity_type/grasped`；不能把其序号与
Lidar 序号硬配对。`PoseEstimate` 必须 `valid=True`、
有有限位置和航向、`frame_id == grid.frame_id`、
`step - pose.step <= 2`、`position_variance <= 400 px^2`。
否则本步不写世界地图，旧地图保留并增加陈旧度。
还要逐射线计算投影不确定度：
`ray_sigma = sqrt(position_variance + d*d*heading_variance)`。
超过 30 px 的射线不写静态或自由证据，避免航向漂移把
远处墙投到错误格；角度方差非有限时整帧拒绝。

7.2 单条射线处理

对每个有限 `distance=d` 且 `0 <= d <= 300+噪声余量`：

```text
a = pose.heading + lidar_angle
hit = d < 295
free_end = min(d, 300) - 7.5
若 free_end <= 0：跳过
从 pose.position 到 free_end 的点用 supercover DDA 走格
沿途每个格加入本帧 free_set
若 hit 且终点在画布内：终点格加入 hit_set 或 dynamic_set
```

接近 300 px 的回波，包括噪声造成的 `d > 300`，
统一只沿射线标记自由至约 292.5 px，不写占据终点。
`d < 0`、NaN、inf 丢弃；`d > 305` 可视为无效并记录异常，
避免错误位置。`d=0` 不从机身中心造出墙。
由于传感器原始 `DistanceSensor` 从射线 hitpoint 提取距离，
没有稳定的“是否命中”布尔位，只能用保守近满量程阈值。

选择 supercover DDA，而非只访问主线像素的普通 Bresenham：
同一个世界线段穿过格角时两个相邻格都须计入；这与 03
返航安全检查共用几何约定。每条 300 px 光线最多约
`ceil(300/20)*2+常数` 次格步进，即约 32 个候选格；
181 条约数千格访问，不在百万像素上更新。

每帧用集合合并所有 ray 的 free/hit/dynamic 格，
同一格每帧静态概率最多更新一次；发生冲突时
`dynamic_set` 先隔离，非动态有效 hit 高于 free，
避免多条射线把同一终点格一次加到饱和。
`free_end=d-7.5` 主要防止测距噪声把真实墙内侧误写为自由。

7.3 更新伪代码

```text
if pose_invalid_or_frame_mismatch:
    age_map_only(); return skipped_stats

free_set, hit_set, dynamic_set = set(), set(), set()
for each (distance, relative_angle) in at most 181 rays:
    validate_numbers()
    cells = supercover_ray(pose, d - 7.5, clip_to_canvas=True)
    free_set.update(cells)
    if reliable_hit_near_endpoint(d):
        cell = world_to_cell(endpoint)
        if semantic_matches_drone_or_bomb(d, relative_angle):
            dynamic_set.add(cell)
        elif semantic_matches_disposal(d, relative_angle):
            mark_structural_unknown_or_soft(cell)
        else:
            hit_set.add(cell)

free_set.difference_update(hit_set | dynamic_set)
apply_free_once(free_set, pose_weight)
apply_dynamic_once(dynamic_set)
update_static_candidates_once(hit_set, pose_weight)
decay_recent_dynamic_and_stale_candidates()
if stable_semantic_change_or_logodds_bucket_changed:
    revision += 1
invalidate_dependent_masks_and_plan_cache()
```

每步先积累本地 ray，再更新概率；不要对 181 条射线的同一格
重复独立加分。地图 `updated_step` 每次处理有效帧都更新；
`revision` 仅在离散三态变化、硬障碍变化、可通行风险档变化、
动态封锁档变化或导入有效 patch 时增加。
原始浮点 log-odds 的微小变动不能导致每步所有路线失效。
若当前路线附近动态层变化但静态图不变，可用局部
`dynamic_revision` 内部计数供路径缓存失效；公共 revision
也应在“可通行性变了”时递增，不能只更新日志。

8. 概率表示与动态障碍

8.1 为什么用 log-odds

三态整数更新太僵硬，简单计数难表达反证和衰减；
首版采用每格静态 log-odds `float32`，未观测为 0。

```text
L_new = clamp(L_old + delta, -4.0, +4.0)
free_delta = -0.35 * pose_weight
confirmed_hit_delta = +1.20 * pose_weight
```

概率与 log-odds 不需要每步都转换：离散状态阈值直接用
`L <= -0.62` 为 FREE，`L >= +0.85` 为 OCCUPIED，
中间为 UNKNOWN。`pose_weight = clamp(1 - ray_sigma/40,
0.25, 1.0)`；方差超过 400 的帧不写图。
单帧重复射线只算一次，独立多帧相同位置可增加置信度。
每 60 步对未更新格做一次懒惰衰减：
`L_effective = L_saved * 0.98 ^ floor(age/60)`，
`age=step-last_measurement_step`；重复查询只能从同一
`L_saved` 计算，不能再次乘衰减因子造成双重衰减。
此参数的半衰期约 2059 步，长回合旧墙仍可逐渐回 UNKNOWN；
新观测到来时先物化衰减再应用增量并更新基准时间。
衰减改变离散状态才增 revision。不要全图每步衰减，
可按行切片分摊或查询时按 last_seen 计算。

8.2 动态实体不过度污染静态层

Lidar 本身看不出命中者是什么，语义 35 射线更稀疏：
在角度差小于约 8 度、距离差小于 `max(15, 0.08*d)` px
时，把相应 Lidar 命中与语义 `DRONE/BOMB` 关联。
这只是保守匹配，不假设两套射线一一对应；
语义 `grasped=True` 的炸弹不应被标为静态墙。
携弹物体对本机外部传感器通常通过
`invisible_when_grasped=True` 隐藏，但仍保持近距自体
回波保护：距本机小于约 25 px 的异常 Lidar 命中
不更新静态层。不能把这一阈值扩大到看不见真正近墙。

未被语义解释的终点先进入“静态候选”而非立刻 OCCUPIED。
同一格至少 3 次、且观察之间隔至少 3 步并有
不同视点（平移约 20 px 或航向变化约 15 度），
才把静态 `+1.20` 应用一次并继续积累；
反复来自同一静止姿态的 181 条射线不能伪造 3 次证据。
未确认候选进入动态/软风险层，短期避障仍能看到它，
但不会永久堵死 A*。若 20 步后不再命中，候选衰减或清零。
静态已确认格若被可靠自由观测多次穿过，按 free_delta
逐渐回 UNKNOWN/FREE，避免旧炸弹离开后留下永久墙。

动态层只存近期命中强度和最后见到步数，
例如 `dynamic_prob *= 0.7 ^ (age/5)`，
超过 20 步未见近似清零；局部短时可暂时封锁、
全局规划则主要加风险成本，不永久修改静态障碍。
回收区本身是可进入的目标，不把语义中心和附近整片
直接写为静态墙；若 Lidar 在其边框有实际命中，
仅对应边框格作为候选，投放近距段依旧靠实时传感器。

误分类无法完全避免：如果语义射线没看到移动无人机，
Lidar 终点可能经过 3 个视点仍被误认静态，
所以必须有时间衰减、反向自由证据和地图重检。

8.3 dtype 与单帧上限

静态、动态 log-odds 用 `float32`；时间戳用 `int32`；
候选命中数用 `uint8`，视点 bin 用 `int32`；
三态图和膨胀 mask 用 `uint8/int8`。
无扫描或传感器禁用时数组保持，`updated_step` 不前进，
查询可据当前步判断整体陈旧，不会因 `None` 报错。

9. 障碍膨胀和代价地图

9.1 两种实际包络

从源码看机身使用 24×24 精灵 hull，保守外接半径取 17 px；
炸弹外接半径 12 px。03 返航方案还把抓取关节相对偏移上界
建议为 40 px，故载弹几何包络 `max(17,40+12)=52 px`。
这些不是控制时读取的真值位置，抓取上界须离线校准。

统一安全半径：

```text
pose_margin = clamp(3*sqrt(position_variance), 8, 30) px
grid_margin = resolution * sqrt(2) / 2
lidar_margin = 3*2.5 = 7.5 px
health_margin = 5 px，健康低于 20 时取 10 px
empty_clearance = 17 + pose_margin + grid_margin
                + lidar_margin + health_margin
carry_clearance = 52 + pose_margin + grid_margin
                + lidar_margin + health_margin
```

在 `r=20`、位姿方差 25 px^2、健康正常时：
空载约 58.7 px，携弹约 93.7 px；向上取整为 59 和 94 px。
这与 03 文档的携弹默认 94 px 一致。方差非有限或
大于 400 px^2 时拒绝新全局路线，不是把不确定性
钳到 30 px 后继续盲走。健康信息由协调器传入清障策略；
若其接口尚未冻结，先用固定 5 px 健康余量，
低健康由任务模块禁投，不偷偷减少包络。

`radius_cells = ceil(clearance / resolution)` 只用于粗略
候选邻域；真正二值膨胀使用圆盘 offset，判定
`hypot(dr,dc)*r <= clearance + grid_margin`。
这里额外的半格对角线是“用障碍格中心近似整格区域”的
保守补偿；上述 59/94 px 是规划器请求的物理安全半径，
离散 mask 实际封锁可能再多约 14 px，不能把二者混为一谈。
这样避免普通方形核多堵路，也避免角落漏检。
地图负责人可预计算不同 clearance 档位的圆盘 offsets。
只有首个静态障碍确认或状态变更时更新相关膨胀区域；
新增障碍立刻 OR 到 mask，移除障碍时可延迟安全地
全图重建（最多旧障碍多挡路，不会放行危险段）。

未知区域策略：

- 携弹、返航安全线段、精确路径：UNKNOWN 一律不可通行。
- 取弹路径：UNKNOWN 默认不可通行；如果目标在未知边缘，
  只规划到可确认的最近安全自由格，最后由局部语义追踪。
- 探索前沿：规划路线终点应是已知可达 FREE 前沿格；
  UNKNOWN 用于信息收益和启发式风险，不作为可执行 A* 节点。
- 如需试探未知，返回 `DEGRADED_DIRECT` 且仅允许实时 Lidar
  控制的近距动作，不伪装成安全 `READY` 全局路线。

代价地图的障碍膨胀外再加软风险环，例如障碍距离
低于 `clearance+40 px` 的自由格按接近程度加 0 到 0.4
风险；动态层加 0 到 0.8 短时风险；未知邻接格加 0.2。
这降低擦墙健康损失，但不可把有硬障碍的格用高价放行。

10. A* 和路径平滑

10.1 搜索状态与边成本

使用 `heapq` 实现 8 邻接 A*；堆节点带 `(f,g,row,col,seq)`
确定性决胜。直移基础长度 `r`，斜移为 `r*sqrt(2)`。
若斜移从 `(r,c)` 到 `(r+1,c+1)`，必须同时检查
`(r+1,c)`、`(r,c+1)` 和目标格均非硬封锁，
并用同一 clearance 的膨胀 mask 防止贴角穿墙。

边成本单位为 px-equivalent：

```text
edge_cost = move_length
          * (1 + 0.6*static_risk + 0.4*dynamic_risk)
          + turn_penalty
```

首版状态只含 `(row,col)`，转向罚可以在从 parent 推断转向
时增加每次 0 到 4 px，但这不严格保持 A* 的最优子结构。
若要严格最优转向成本，状态改成 `(row,col,heading_bin)`；
首版建议把 `turn_penalty=0`，由路径平滑后的转角速度控制器
处理转向，避免错误声称带转向最优。
UNKNOWN 在可执行搜索中是硬禁格；用于探索评分时可另给
未知估计价，不进入 `PathPlan.status=READY` 的结果。

启发函数取八方向 octile 距离：

```text
h = r * (max(dx,dy) + (sqrt(2)-1)*min(dx,dy))
```

其中 dx/dy 是列/行差，风险非负，故启发不高估基础
几何距离。`total_cost` 是包含风险的最终搜索 g 值，
`geometric_length_px` 单独保存纯路径几何长度；
02 竞价比较用后者再把风险作为独立代价项，避免双重计费。

10.2 起点、目标、预算和状态

先校验 pose/frame、地图版本、有限 goal、地图边界。
起点所在格 UNKNOWN 时，如果 pose 可信且该位置的
实时 Lidar 周围可用，可只把起点当本次搜索的临时可行
种子，不修改静态地图；它的所有出边仍必须进入已知 FREE。
如果起点硬阻挡，在半径最多 40 px 的邻格找可证实 FREE
替代；找不到返回 `START_BLOCKED`。此替代只解决定位/栅格
误差，不能把一个真正被墙包围的点当已穿出墙。

目标落在静态障碍或动态炸弹所在格时，在目标容差
`goal.tolerance` 内搜最近安全 FREE 格；
取弹目标优先找语义可见的近距等待点，后续交抓取控制；
回收目标同理，A* 只带到能触发近距投放的位置。
若容差内没有 FREE 返回 `GOAL_BLOCKED`；
目标本身越界返回 `GOAL_OUT_OF_BOUNDS`，不偷偷夹到边界。
若起点与候选终点同格且已在容差内，返回 `AT_GOAL`。

搜索每次最多 1500 次节点扩展或 5 ms 工程时间预算；
成本询价最多 500 次或 2 ms。超出立即返回
`BUDGET_EXCEEDED`，不把“尚未找到”说成 `NO_PATH`。
如果已完整搜索可达连通区仍无路径，才返回 `NO_PATH`。
map revision 在规划过程中变化则 `STALE_MAP`；单线程实现
通常只会在两个控制步骤之间变化，但要防缓存重用旧版本。
对于正式导航搜索，`GridPathPlanner` 保存一个按缓存键索引的
`SearchSession(open_heap, g_score, parent, closed, expansions)`；
下一控制步若键和 revision 都没变，则继续弹堆而非从零重算。
累计扩展超过地图格数加冗余上限、目标改变或 revision 改变时
终止 session；`BUDGET_EXCEEDED` 期间不返回未到终点的路点。
成本询价可以不保存 session，但最多 3 个/步，并把状态传给
竞价模块做保守回退。

核心搜索伪代码：

```text
session = reuse_or_create(start, goal, clearance, revision)
while heap and expanded_this_step < 1500 and under_5ms_target:
    current = heappop_min_f_then_g_then_cell()
    if stale_heap_entry(current): continue
    if current in closed: continue
    if current is acceptable_goal_cell:
        return reconstruct_and_validate(current)
    closed.add(current)
    for neighbor in eight_neighbors(current):
        if blocked_or_diagonal_cuts_corner(neighbor): continue
        candidate_g = g[current] + nonnegative_edge_cost()
        if candidate_g < g[neighbor]:
            parent[neighbor] = current
            g[neighbor] = candidate_g
            heappush(neighbor, candidate_g + octile_h(neighbor))
if heap: return BUDGET_EXCEEDED and keep_session()
return NO_PATH and discard_session()
```

10.3 路径还原和平滑

从 parent 链还原 `(row,col)`，转每格的真实交集中心坐标；
不把当前起点放入 waypoints；最后若目标坐标本身有安全
落脚区且线段可证实安全，可替换最后格中心为目标点，
否则终点为安全替代格，`reason` 记录 goal snapped。
连续同方向格中心先合并，再尝试用
`GridQueryService.check_segment()` 作可视捷径；
只有 `status=SAFE`、frame 和 revision 一致才允许删除中间点。
候选最多向前看 12 个格转角，逐步预算受控；
不能只用 RDP 把 U 形墙压成穿墙直线。

`PathPlan` 缓存键至少包括：

```text
(start_cell, goal_id, goal_cell, tolerance_bucket,
 carrying, clearance_bucket, unknown_policy, map_revision)
```

持弹变化、目标换 id、地图 revision 变化、当前位置偏离
旧路线超过 35 px、当前/下一段被 Lidar 持续阻挡时失效。
无变化时允许 15 步以内复用已校验路径，只更新下一 waypoint；
不每步从头跑全图 A*。动态机体路过只先做实时停/绕，
持续 25 步再重规划，避免每次相遇都搜索。

10.4 成本查询与误差边界

`estimate_cost()` 复用相同膨胀层和 8 邻接 A*，
但不做整条路的详细平滑；返回纯几何长度与
`READY/NO_PATH/BUDGET_EXCEEDED/STALE_MAP` 等状态。
同一地图与同一离散目标下，未平滑格路径长度通常是
连续可见路线长度的上界；不是“真实飞行时间”的严格上界，
因为低级控制转向、动态避障和地图误差会改变实际长度。
预算不足时返回 `BUDGET_EXCEEDED`，由 02 方案使用
惩罚化欧氏距离作临时竞价近似，不能把它误报成 A* 精确成本。
10 个无人机每步不能各对所有炸弹搜索，协调器只给
粗排前 3 个候选询价，缓存 15 步并随 revision 失效。

11. 输入契约

每步由协调器组装，不要求地图类直接读取 `DroneAbstract`：

- `pose: PoseEstimate`：定位模块输出，世界 px/rad，
  带方差、frame、逻辑步；无效则本步不投影 Lidar。
- `lidar_distances: Sequence[float]`：控制器从
  `lidar_values()` 复制为只读 181 个距离，单位 px；
  `None` 或非 181 个则跳过本步建图，不清空旧图。
- `lidar_angles: Sequence[float]`：`lidar_rays_angles()`，
  181 个机体系 rad，通常固定；shape 不符拒绝整帧。
- `semantic_hits: Sequence[SemanticObservation]`：
  与当前 Lidar 同步的 35 射线检测子集，类型来自语义枚举；
  不同帧或角度/距离非有限则不用作动态标签。
- `size_area: (W,H)`：控制器的 `size_area` 或 MiscData，
  世界 px；无效尺寸时不创建地图，规划返回 `NO_POSE`
  或显式 `INVALID_MAP` 内部错误，不得猜固定 Map01 大小。
- `carrying: bool`：`bool(grasped_bombs())`，
  决定膨胀 profile；本模块不读取炸弹实体内部位置。
- `goal: NavigationGoal`：目标分配、返航或探索模块产生；
  缺失时只建图不规划，坐标 frame 须与地图一致。
- `step: int`：`elapsed_timestep`，用于衰减、频率和缓存；
  不能混用秒数。
- `peer_patch: Optional[dict]`：codec 验证后的稀疏摘要；
  首版关闭接收即可运行，不能假定全队实时共享全图。
- `health: int`：协调器可选传给安全半径策略，
  不是从地图猜；缺失取正常 5 px 余量。

默认所有传感器数组只在本控制步骤有效，
`PoseEstimate.step` 与 scan 步差最多 2；
若要队友转发观测，必须携带源时间、frame 和方差，
不允许把收到的旧点当本机当前射线重新投影。

12. 输出契约

给其他模块的具体只读返回：

- `OccupancyGridView`：给探索模块 `state_at()`、
  `unknown_count()`、`risk_near()`；只查，不得写内部数组。
- `PathPlan`：给协调器，只有 `READY` 的 waypoints
  可执行；运动层仍加 Lidar 安全检查。
- `(status,length_px,revision)`：给任务分配模块
  做取弹/返航竞价；状态不是 `READY` 时长度不可当真值。
- `SegmentCheck` 和 `segment_is_safe()`：给返航模块，
  只有 `SAFE` 是捷径许可。
- `debug_snapshot(max_size=...)`：低频在本地保存状态数、
  地图 revision、A* 开销；不对普通通信广播整图。
- `export_sparse_patch()`：可选紧凑摘要给共享消息层选择发送。

实际路径对象示例（仅字段演示，不代表现有算法已算出）：

```python
PathPlan(
    status="READY",
    waypoints=((-312.0, -96.0),
               (-104.0, -112.0), (88.0, 42.0)),
    total_cost=487.6,
    map_revision=73,
    created_step=1204,
    reason="astar_8_connected_safe_smoothed",
    geometric_length_px=461.2,
    clearance_px=59.0,
    goal_id="bomb:world:d6:17",
)
```

`total_cost` 单位为 px-equivalent，不能直接当作
`geometric_length_px` 传给 02 模块，否则风险会重复计费。
`waypoints` 是不可变 tuple，协调器仅可读下一点；
任何修改目标/清障规则都应重新 `plan()`。

13. 地图共享接口

首版每架无人机只维护自己的地图，不广播 NumPy 矩阵。
例如 Map04 约 4731 格，哪怕一格只 1 字节，完整广播
也要数 KB；通信半径 250 px、每机每步只能发送一个包，
还要给任务 bid、携弹和探索租约留位置。

未来允许最多 12 个单元、约 160 字节的稀疏补丁，
以“新确认高置信 OCCUPIED”为主，最多附 4 个高置信 FREE
单元用于纠正旧墙。只发格索引和量化置信度，不发完整历史：

```python
{
  "v": 1, "origin": [-830.0, -561.0], "r": 20,
  "frame": "world", "source": 6, "rev": 73,
  "seq": 9, "step": 1204,
  "cells": [[22, 41, 2, 3], [22, 42, 2, 3]]
}
```

每个 cell 为 `[row,col,state,confidence_bucket]`，
`state=2` 表示已确认占据，`state=0` 表示高置信自由。
外层仍是统一 `blue-team-v2` 消息：

```python
{"kind":"blue-team-v2", "v":2, "id":6, "step":1204,
 "task":{...}, "explore":{...}, "map":{...}}
```

消息优先级由 codec 统一管理：`CLEAR/CARRY`、关键 bid/lease
先于 map；map 过大时首先丢弃或延迟。
不同 frame、origin、resolution、尺寸或不兼容版本的 patch
先拒绝；若定位模块明确给出可信坐标变换，可经定位负责人
转换后再融合，首版不做跨 frame 融合。
记录每个 `(source,seq)`，重复或倒退不刷新置信度；
`source_rev` 仅用于该来源内比较，不能拿它与本机 revision
大小直接比较。队友 patch 只给低权重佐证，
不能单条 patch 直接把本机已观测 FREE 改成硬 OCCUPIED。
接收时间用于 TTL，例如 60 步；发送步仅用于去重/新旧比较。
`export_sparse_patch()`/`ingest_sparse_patch()` 即使首版不启用，
接口和字段仍固定，便于以后联调。

14. 单步调用时序

```text
1. 控制器读 measured GPS/compass、Lidar 181 值、语义命中、
   是否携弹、健康和当前逻辑步
2. localization 生成 PoseEstimate；不能用 true_position
3. codec 验证可选 peer map patch
4. OccupancyGrid.update_from_scan() 更新静态候选/动态层/三态
5. 若有 patch，再 ingest_sparse_patch()；更新 revision
6. 协调器把最新 OccupancyGridView 提供给探索、任务、返航
7. 这些模块选择唯一主 NavigationGoal
8. GridPathPlanner 复用缓存或按预算 A*，返回 PathPlan
9. READY：协调器选当前 waypoint；运动层仍做 Lidar
   减速/脱困，并把偏离、墙挡事件回报给规划器
10. 非 READY：按状态选择等待定位、换目标、近距扫描或退化
11. 统一消息编码器仅缓存小 map patch；下一广播周期发送
```

`GuiSR` 在 `control()` 前调用 `define_message_for_all()`，
物理步末才传输，所以本步生成的地图摘要不会在本步
被队友处理。规划不能依赖同一步远端地图回应。

15. 与现有代码的迁移步骤

- `_lidar_sector_min()`、`_lidar_path_min()`：保留为实时
  安全层；同一帧数据另送建图，不让建图破坏原扇区逻辑。
- `_apply_lidar_avoidance()`：保留；A* 的 waypoint
  只是目标，不保证动态环境当前可直冲。
- `_run_lidar_escape_if_needed()`：保留；触发脱困后通知
  路径进度监视器，不把脱困侧移误判成路径偏离故障。
- `_move_toward()`：GPS 可用时继续服务下一 waypoint；
  GPS 关闭但融合定位有效时，需新增读取 `PoseEstimate`
  的运动适配器，不能调用父类后期待它自行使用融合估计。
- `_control_to_remembered_bomb()`：先拿 `PathPlan.READY`
  waypoint，再用现有局部运动；`NO_PATH` 时暂缓该目标并
  告知任务分配模块，不循环朝炸弹点撞墙。
- `_control_carry()`：优先遵循 03 返航模块有效路线；
  原路线失效才调用携弹 A*；看见回收区后保留近距投放。

渐进开关：

1. `MAP_ENABLED`：只记录地图并输出日志，不改动作。
2. `COST_QUERY_ENABLED`：给 02 模块提供真实路径成本；
   不可用时它仍用保守几何估计。
3. `BOMB_ASTAR_ENABLED`：记忆目标导航走 A*。
4. `RETURN_ASTAR_ENABLED`：03 模块返航失败时调用 A*。
5. `FRONTIER_ASTAR_ENABLED`：01 模块前沿目标走 A*。
6. 任一阶段评分/稳定性退步，可关对应开关退回
   原 Lidar 反应式导航，但不要误称其保证不撞墙。

17. 复杂度、内存和刷新预算

Map04 最大画布约 1660×1122，20 px 分辨率得到
83×57=4731 格；Map05 为 60×60=3600 格。
一个 `float32/int32` 层约 18,924 字节，`uint8` 层
约 4,731 字节。

建议常驻数组：静态 L、静态最后观测步、候选最后步、
候选视点 bin、动态 L、动态最后步、静态距离场、风险层，
共 8 个 4 字节层约 151,392 字节；候选计数、三态、
空载膨胀、携弹膨胀 4 个 1 字节层约 18,924 字节；
合计约 170,316 字节，即约 166 KiB/机，不含 Python
对象和 LRU 缓存。A* 的 g、parent、closed 再约
42,579 字节，合计约 208 KiB/机的主要 NumPy 数组。
10 机大约 2 MiB 数组，真实峰值需实测 heap 与缓存。

每有效扫描最多处理 181 条，每条最多约 32 格，
单帧约 6000 格访问；可每 2 步融合一次静态图，
但动态近距层和原始 Lidar 安全控制每步更新。
静态 candidate/自由证据可按步采样，不过采样间隔
过大会影响建图准确率，需用 Map01 对照测量。
三态 revision 只在规划相关档位变化时递增。

膨胀 mask 新障碍局部增量 OR；每 20 步或删除障碍后
分片重建全图。最大携弹半径约 94 px，20 px 格上
圆核直径约 11 格；全图重建朴素上界约
4731×121≈57 万个邻域判断/配置，不能每步重复 10 次。
可以用 NumPy 对每个圆核 offset 平移 OR 布尔数组；
若实测仍慢，分片每步 10 个 offset 并在完成前
保持旧 mask 的保守封锁。新增障碍须立即局部写入，
不能等完整重建才影响当前路线安全。

A* 正式查询最多 1500 扩展，单次目标 5 ms；
竞价成本查询最多 500 扩展、2 ms，最多 3 次/步。
最坏 10 机同步重规划可使 CPU 明显升高，因此每机
按 `drone_id mod 3` 错开非紧急规划，紧急携弹失效
优先处理。5 ms/2 ms 是在目标机器上待验证的工程目标，
非 Python 调度的硬实时保证；超时返回 `BUDGET_EXCEEDED`。

缓存键包含 frame、map_revision、起终点格、goal_id、
clearance 档、携弹标记和目标容差。地图变化时只保留
仍可逐段复验的旧路线；不能仅因缓存存在就把旧方案
视为可执行。低频地图快照只写本地调试文件，不进入
正式通信包，也不在每步弹图形窗口。

18. 失败模式和降级策略

- GPS/指南针不可用：无可比较 world 位姿时暂停地图融合和
  A*，保持旧图，转现有 Lidar 局部避障或等待重定位。
- 位姿高方差：降低或停止概率更新，扩大 clearance；
  超过阈值停止发布新 `READY`。
- Lidar 禁用或数组异常：保留旧图并标陈旧，
  不能把缺失回波当 300 px 空旷。
- 语义误匹配：动态端点快速衰减、静态端点需多视点确认；
  仍可能误分类，必须允许自由反证清除。
- 地图 UNKNOWN 占大多数：不凭空规划全局捷径；
  探索层逐步进入可观察边界，局部 Lidar 仍有效。
- 动态无人机挡住当前路线：先局部停/绕，持续 25 步
  再重规划；不把它永久写成墙。
- 新发现墙或地图 revision 变化：当前/下一段先重检，
  不安全则 `STALE_MAP` 并请求重规划。
- 起终点贴墙：在目标容差内找安全替代格，
  找不到返回显式阻塞状态，不偷偷穿墙。
- 携弹太宽无法通过狭道：返回 `NO_PATH`，由 03 模块
  寻原轨迹可逐段检查的回退或暂停，不能缩小 radius 赌通过。
- A* 预算耗尽：返回 `BUDGET_EXCEEDED`，下一步续算或
  使用旧安全路径；不能误报 `NO_PATH`。
- 不同 frame 地图补丁：拒绝或等待定位转换，
  不能直接叠加到本机 world 图。

21. 尚需确认的问题

1. 定位负责人能否提供与 Lidar 同一控制步的世界位姿和
