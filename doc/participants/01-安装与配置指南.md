# Swarm-Rescue 安装与配置指南

本文档面向参赛选手，涵盖环境搭建、仿真运行、地图工具使用和常见问题排查。阅读完本文后，建议继续阅读 [`02-队伍开发指南.md`](02-队伍开发指南.md) 和 [`03-提交检查与打包.md`](03-提交检查与打包.md)。

---

## 1. 环境要求

| 要求项 | 说明 |
|--------|------|
| **操作系统** | 推荐 Ubuntu 20.04+ / Debian 11+，也支持 macOS 12+ 和 Windows WSL2 |
| **Python** | Python 3.8+（推荐 3.10 或更高版本） |
| **GPU / OpenGL** | OpenGL 4.4+（GLSL 4.40）。绝大多数现代 GPU 均满足该要求 |
| **内存** | 建议 4GB+ 可用内存 |

> **注意**：Lidar 和语义传感器依赖 GPU Compute Shader（GLSL 4.40）。如果 OpenGL 版本不足，模拟器会自动降级为 CPU 模式，性能会显著下降。

## 2. 安装步骤

### 2.1 克隆项目并创建虚拟环境

```bash
# 进入项目根目录
cd swarm-rescue

# 创建 Python 虚拟环境
python -m venv .venv

# 激活虚拟环境
source .venv/bin/activate
```

### 2.2 安装依赖

```bash
# 以可编辑模式安装项目及开发依赖（包含 pytest 等）
pip install --editable .[dev]
```

> **说明**：`--editable` 模式意味着你对 `src/swarm_rescue/solutions/` 目录下代码的修改会立即生效，无需重新安装。

### 2.3 安装无头运行所需的工具（仅服务器）

如果你在没有显示器的 Linux 服务器上运行，需要安装 xvfb：

```bash
sudo apt install xvfb
```

## 3. 验证安装

运行一次本地仿真来确认一切正常：

```bash
.venv/bin/python -m swarm_rescue.launcher -c config/competition_rescue_eval_plan.yml
```

成功运行后，你将看到一个 **GUI 窗口**，其中包含：

- **蓝色小方块**：你的无人机（默认 10 架）
- **黑色线段和矩形**：墙壁
- **红色圆形**：炸弹（Bomb），需要被找到并处理
- **绿色矩形**：处置中心（DisposalCenter），炸弹需要被送到这里

无人机从地图定义的出生区（`_start_area_drones` 中心点周围）出发。按下窗口中的 **Play/Pause** 按钮即可开始仿真。无人机将执行 `my_drone_eval.py` 中定义的策略。

## 4. 无头模式

在无显示器的服务器上运行仿真（如通过 SSH 连接到远程 Linux 服务器）：

```bash
xvfb-run -s "-screen 0 1920x1080x24" .venv/bin/python -m swarm_rescue.launcher \
    --headless -c config/competition_rescue_eval_plan.yml
```

- `xvfb-run -s "-screen 0 1920x1080x24"`：启动一个虚拟的 X 显示缓冲区
- `--headless`：告知模拟器不打开真实显示窗口

无头模式适合在远程服务器或 CI 环境中批量运行仿真。默认会启用 `.npz` 状态录制（轻量级，~150KB/轮），不需要视频编码。

录制的仿真回放文件保存在 `results_swarm_rescue/teamNNN_XXX/recordings/` 目录下。你可以使用以下命令回放：

```bash
.venv/bin/python -m swarm_rescue.launcher --replay <recording.npz>
```

回放控制：**SPACE** 播放/暂停，**LEFT/RIGHT** 进退帧，**UP/DOWN** 调速，**Q** 退出。

如果你需要传统的 `.avi` 视频录制，可以在 `evaluation_plan` 的 YAML 中设置 `video_capture_enabled: true`，或设置环境变量：

```bash
# 录制视频（半分辨率，性能影响较大）
VIDEO_RECORDING_SCALE=0.5 xvfb-run -s "-screen 0 1920x1080x24" \
    .venv/bin/python -m swarm_rescue.launcher --headless -c config/competition_rescue_eval_plan.yml
```

## 5. 擂台（Competition）模式

在正式比赛环境中，直接访问无人机真值（如 `true_position()`、`true_angle()`）的 API 是被拦截的——这模拟了真实场景中无法获得精确全局定位的情况。

你**必须**在提交代码前在 `--competition` 模式下测试你的策略：

```bash
.venv/bin/python -m swarm_rescue.launcher --competition -c config/competition_rescue_eval_plan.yml
```

在 competition 模式下：

- 在 `control()` 函数内调用 `true_position()`、`true_angle()`、`true_velocity()`、`true_angular_velocity()` 会**抛出异常**
- 你应始终使用传感器 API：
  - `measured_gps_position()` — 获取带噪声的 GPS 位置
  - `measured_compass_angle()` — 获取带噪声的罗盘角度
- 直接访问 `self.position` 或 `self.angle` 也是**不允许**的

> **提示**：提交前务必在 competition 模式下至少完整运行一次，确保没有使用任何真值 API。

## 6. 红蓝队双阶段演示

该项目支持两种队伍模式：

- **蓝队（Rescue）**：搜索、抓取、处置炸弹。默认模式。
- **红队（Place）**：探索地图，在适合的位置放置炸弹。

分别运行红/蓝队示例配置：

```bash
# 红队（放置）
.venv/bin/python -m swarm_rescue.launcher -c config/competition_place_eval_plan.yml

# 蓝队（救援）
.venv/bin/python -m swarm_rescue.launcher -c config/competition_rescue_eval_plan.yml
```

## 7. 地图编辑器使用

项目提供了一个图形化地图编辑器，可绘制自定义地图的墙壁、起点区域和处置中心，并支持画布尺寸调整、元素选中与坐标精调。地图创建整体流程见 `doc/developers/04-地图开发指南.md`。

### 7.1 启动编辑器

```bash
.venv/bin/python -m swarm_rescue.tools.map_wall_editor
```

编辑器会自动尝试使用 **PySide6**；如果 PySide6 未安装，则回退到 **Tkinter**（Python 内置），两个版本功能一致。

### 7.2 工具按钮说明

工具栏提供以下工具（单选按钮）：

| 工具 | 说明 | 操作方法 |
|------|------|----------|
| **选择** | 左键选中元素进行编辑 | 点击元素即选中（重叠时选最上层）；右键点击元素可直接删除 |
| **线段墙 (6px)** | 绘制黑色线段墙壁（线宽 6px） | 点击两个点（起点和终点），创建一条线段墙 |
| **矩形墙** | 绘制实心矩形墙壁 | 点击两个对角点，创建填充矩形 |
| **起点区域** | 标记无人机出生区域（全局唯一） | 点击两个对角点确定矩形。新绘制会替换旧的；只取中心点作为出生坐标 |
| **DisposalCenter** | 标记炸弹处置中心（全局唯一） | 点击两个对角点确定矩形。新绘制会替换旧的 |

### 7.3 功能按钮

| 按钮 | 说明 |
|------|------|
| **保存 JSON** | 将当前画布上所有元素保存为 JSON 文件 |
| **加载 JSON** | 从 JSON 文件恢复画布内容；画布自动适配 JSON 尺寸 |
| **删除选中** | 删除当前选中的元素（选中后在属性面板旁出现） |
| **导出 PNG** | 将画布渲染导出为 PNG 图片 |
| **画布宽 / 高 / 应用尺寸** | 调整画布尺寸，见 [7.4](#74-画布尺寸调整) |

### 7.4 画布尺寸调整

- 默认尺寸为 **1113×750** 像素
- 在右上角宽度/高度输入新值后点击「应用尺寸」，即调整地图尺寸（范围 100 ~ 10000 像素），以左上角为锚点
- 缩小画布时，超出新边界的元素被自动裁剪；退化为零长度/零面积的元素自动删除
- 建议：新建不同尺寸的地图时，先设置好画布尺寸再开始绘制

### 7.5 选中与坐标精调

切换「**选择**」工具后，左键点击元素即可选中，选中元素显示为高亮：

- **属性面板**：第二行显示被选元素的坐标（线段墙为 `x1/y1/x2/y2` 两端点；矩形墙/起点区域/DisposalCenter 为左上/右下对角点），直接修改输入框后按 **回车** 应用
- **删除**：选中后点击「删除选中」按钮，或直接在画布上**右键**点击元素删除
- 矩形坐标会自动归一化（保证 `top_left <= bottom_right`）

### 7.6 基本操作流程

1. （可选）先用 `walls_to_json` / `png_to_json` 把现有墙体或 PNG 图片转成 JSON，再加载
2. 选择 **线段墙** 或 **矩形墙**，在画布上点击绘制墙壁
3. 选择 **起点区域**，用两个对角点标出无人机出生区
4. 选择 **DisposalCenter**，用两个对角点标出处置中心
5. 如需不同尺寸，用「画布宽/高 + 应用尺寸」调整
6. 切到 **选择** 工具，在属性面板精调元素坐标或删除多余元素
7. 点击 **保存 JSON**，导出 `.json` 文件供 `json_to_map` 使用

### 7.7 提示

- 绘制时：单击记录首点，移动鼠标显示虚线预览，再次单击完成绘制
- 起点区域 / DisposalCenter 全局唯一，重复绘制会替换旧区域
- 状态栏实时显示当前工具与操作结果

## 8. 从 JSON 生成地图代码

使用地图编辑器保存 JSON 后，可以通过 `json_to_map` 工具生成完整的 Python 地图代码：

```bash
.venv/bin/python -m swarm_rescue.tools.json_to_map map_data/map_01.json --name custom_example
```

参数说明：

| 参数 | 说明 |
|------|------|
| `map_data/map_01.json` | 第一个位置参数，地图编辑器导出的 JSON 文件路径 |
| `--name custom_example` | **必填**，地图名称（字母数字和下划线），用于生成文件名和类名 |
| `--maps-dir` | 可选，生成的 Python 地图代码输出目录，默认为 `src/swarm_rescue/maps/` |

生成的文件：

| 输出文件 | 说明 |
|----------|------|
| `maps/map_custom_example.py` | 地图类定义，继承 `MapAbstract`，含处置中心、起点区域中心点、无人机出生位置 |
| `maps/walls_custom_example.py` | 墙壁定义文件，包含 `add_walls()` 和 `add_boxes()` 函数 |

生成的地图类默认设置：

- `_max_timestep_limit = 7200`，`_max_walltime_limit = 1440` 秒
- 无人机数可通过 `number_drones` 参数覆盖，默认 10
- 起点区域取矩形中心作为 `_start_area_drones` 出生中心点；DisposalCenter 按其矩形生成
- `_bombs_pos` / `_bombs_path` 为空，炸弹位置需自行添加

> **注意**：生成的地图类需要手动在 `launcher.py` 顶部 import 才能被 YAML 配置引用。具体流程详见开发者文档。

## 9. 从位图创建地图

如果你习惯用图像编辑软件（Photoshop、GIMP、画图）绘制地图，可以先用 `png_to_json` 把黑白图片矢量化成编辑器 JSON，再在编辑器中精修。

> 这里需要 **黑色 = 墙体、白色 = 背景** 的线稿图。

```bash
.venv/bin/python -m swarm_rescue.tools.png_to_json input.png output.json [--export-png]
```

| 参数 | 说明 |
|------|------|
| `input.png` | 输入 PNG 路径（黑墙白底） |
| `output.json` | 输出编辑器 JSON 路径 |
| `--export-png` | 可选，同时导出识别结果的渲染 PNG 便于对比 |

算法采用两阶段：实心矩形块 → `rect_wall`，线条墙体（骨架化 + 霍夫变换）→ `line_wall`。矢量化精度有限，**导入后需在地图编辑器中检查精修**。

生成的 JSON 直接用编辑器加载，继续补起点区域、DisposalCenter 并保存，然后用 `json_to_map` 生成地图代码。

## 11. IDE 配置建议

### PyCharm

1. 打开项目文件夹 `swarm-rescue`
2. 设置 Python 解释器：`File` → `Settings` → `Project: swarm-rescue` → `Python Interpreter` → 选择 `.venv/bin/python`
3. 将 `src/` 目录标记为 Sources Root（右键 `src/` → `Mark Directory as` → `Sources Root`）

### VS Code

1. 打开项目文件夹
2. 按 `Ctrl+Shift+P`，搜索 `Python: Select Interpreter`，选择 `.venv/bin/python`
3. 在 `.vscode/settings.json` 中建议添加：
   ```json
   {
     "python.analysis.extraPaths": ["src"],
     "python.autoComplete.extraPaths": ["src"]
   }
   ```

### 文件开发位置

你的所有策略代码应放在 `src/swarm_rescue/solutions/` 目录下：

```
src/swarm_rescue/solutions/
├── my_drone_eval.py      ← 你的主要策略代码
└── your_extra_module.py   ← 可选的辅助模块
```

## 12. 常见问题

### 12.1 macOS：GPU Shader 被禁用

macOS 默认不支持 Compute Shader（GLSL 4.40），因此模拟器会自动回退到 CPU 射线求交，性能显著降低。这是正常现象，不影响代码正确性，但仿真速度会慢 5 倍以上。

### 12.2 无头服务器：没有 GUI

如果你在没有显示器的服务器上运行，必须使用 `xvfb-run`（参见第 4 节）：

```bash
xvfb-run -s "-screen 0 1920x1080x24" .venv/bin/python -m swarm_rescue.launcher \
    --headless -c config/competition_rescue_eval_plan.yml
```

如果未安装 xvfb：

```bash
sudo apt install xvfb
```

### 12.3 OpenGL 版本不足

如果 `opengl_info` 显示 OpenGL 版本低于 4.4，你可以关闭 GPU Shader 功能以使用 CPU 模式运行：

在 `src/swarm_rescue/simulation/gui_map/closed_playground.py` 文件中找到 `ClosedPlayground.__init__` 方法，将 `use_shaders` 参数设置为 `False`：

```python
self._playground = ClosedPlayground(size=self._size_area, use_shaders=False)
```

> **警告**：关闭 Shader 后性能会明显下降（约为 GPU 模式的 1/5）。仅在无法升级 GPU 驱动时使用此方法。

### 12.4 WSL2：GPU 设置

在 WSL2 中运行需要：

1. 确保宿主机安装了支持 WSL2 GPU 的显卡驱动
2. 在 WSL2 中安装必要包：
   ```bash
   sudo apt install mesa-utils
   ```
3. 检查 OpenGL 版本：
   ```bash
   glxinfo | grep "OpenGL version"
   ```

如果 `glxinfo` 未找到，先安装 `mesa-utils`。

### 12.5 虚拟环境激活失败

```bash
# 确保使用正确的 Python 版本创建虚拟环境
python3 --version
python3 -m venv .venv
source .venv/bin/activate
```

如果 `source` 在非 bash/zsh shell 中不可用，使用：

```bash
. .venv/bin/activate
```

### 12.6 pip install 失败

确保 pip 为最新版本：

```bash
pip install --upgrade pip
```

如果某些依赖（如 `arcade`、`PySide6`）安装失败，检查系统是否缺少必要的编译工具：

```bash
# Ubuntu/Debian
sudo apt install build-essential python3-dev

# macOS
xcode-select --install
```

### 12.7 导入错误：找不到模块

如果你运行仿真时遇到 `ModuleNotFoundError`，确保已以可编辑模式安装：

```bash
pip install --editable .[dev]
```

之后运行仿真时务必使用 `.venv/bin/python` 而非系统 Python。
